# eggbabe 蛋宝宝普通小程序 V3.6

这是基于现有 MVP 增量收敛的微信普通小程序生产前端。孵化前继续以已确认的 V3.5 为基线；破壳过程与破壳后以《蛋宝宝小程序_V3_6_PRD》为主，《蛋宝宝_日常陪伴系统_结构说明_v0.3》补充空间与素材结构；两者冲突时以主 PRD 为准。落地与未决项见 `docs/蛋宝宝小程序_V3.6_破壳后实现口径.md`；发布门禁见 `docs/蛋宝宝普通小程序_合规与提审清单.md`，前后端边界见 `docs/蛋宝宝小程序_技术与数据接口规格.md`。

公开仓库：<https://github.com/octopusgump/eggbabe-miniprogram>

## 已完成的前端流程与接口适配

微信授权进入 → 输入激活码 → 绑定唯一蛋宝宝 → 按日开放修炼内容 → 被动与主动修炼值达到 100% → 完成昵称、出生礼物和孵化回顾 → 生成一蛋一份的收藏卡 → 在三屏生活空间查看此刻状态、完成对应动作，并仅在允许的小场景原地说话。

孵化期使用统一的小房间场景，不提供场景选择或切换；前端支持四季底图、上海天气粒子、昼夜光线和五类默认小物反馈，正式环境数据由 CTO 侧下发。登录、绑定、改名、对话、破壳和收藏卡均已建立 live 服务适配，后端未确认时不展示业务成功。

## 微信开发者工具预览

1. 打开微信开发者工具，导入 `01_MiniProgram_MVP` 文件夹，而不是单独导入 `miniprogram/`。
2. 微信开发者工具的 `develop` 环境自动进入“开发验收模式”，页面会显示明确标识，数据只写入 `eggbabe_demo_*` 命名空间。
3. 勾选隐私政策并点击“进入开发验收”；在添加页手动输入固定验收码 `EGGD1`。
4. 绑定后按 V3.5 的服务端内容日与修炼值测试孵化互动；首页不提供跳过条件或直接破壳入口。
5. `trial` 与 `release` 固定使用 `live`；正式后端未接入时继续阻断，不允许本地 demo 假成功。
6. 真机测试正式登录、生命周期与跨设备数据时，仍需 CTO 提供测试服务器和测试账号。

## 当前实现边界

- 本目录只保留前端页面、H5 与 `services/` 接口适配层，不包含云函数，也不调用 `wx.cloud.*`。
- 普通包不注册或实现虚拟资源、商店、背包、随机产出、系列收集或任务能力；修炼百分比只由服务端计算，首页不展示进度条。
- 内部开发验收使用微信 `develop` 独立构建与 `mode=demo` 存储；`trial` / `release` 固定为 `live`，且没有用户可操作的模式切换入口。
- demo 使用固定身份、固定实体蛋、固定生命周期控制和固定收藏卡素材，不调用正式接口，也不进入正式统计。
- H5 收藏卡把分享图数据回传小程序，由微信相册能力保存；开发者工具里建议同时用真机验证授权流程。

## 用户资料与公开 ID

- 普通版前端只展示昵称、头像和服务端用户编号。
- 用户 ID、实体蛋 ID、收藏卡 ID 与身份编号均由服务端生成，前端不随机补造。
