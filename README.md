# eggbabe 蛋宝宝普通小程序 v2.28

这是基于现有 MVP 增量收敛的微信普通小程序生产前端。当前产品规范为 `docs/蛋宝宝小程序_V2_PRD.md` v2.28；发布门禁见 `docs/蛋宝宝普通小程序_合规与提审清单.md`，前后端边界见 `docs/蛋宝宝小程序_技术与数据接口规格.md`。

公开仓库：<https://github.com/octopusgump/eggbabe-miniprogram>

## 已完成的前端流程与接口适配

微信授权进入 → 输入激活码 → 绑定唯一蛋宝宝 → 命名 / 轻触 / 长按 / 说话 / 自由陪伴 → 到达可承接破壳时刻 → 生成一蛋一份的收藏卡 → 在生活场景获得纯内容反馈并继续对话。

孵化期使用统一的小房间场景，不提供场景选择或切换；前端支持四季底图、上海天气粒子、昼夜光线和五类默认小物反馈，正式环境数据由 CTO 侧下发。登录、绑定、改名、对话、破壳和收藏卡均已建立 live 服务适配，后端未确认时不展示业务成功。

## 目录

```text
project.config.json          微信开发者工具项目配置
miniprogram/                 小程序源码

scripts/                     项目完整性校验
```

`project.private.config.json` 属于微信开发者工具的本机配置，已加入 `.gitignore`，不会提交到公开仓库。

## 微信开发者工具预览

1. 打开微信开发者工具，导入 `02_MiniProgram_MVP_20260710_GPT` 文件夹，而不是单独导入 `miniprogram/`。
2. 未配置正式 AppID 时可保留 `touristappid` 进行界面预览。
3. 勾选隐私政策后进入普通版未绑定状态。
4. 激活、生命周期、破壳和收藏卡只接受 CTO 服务端确认的 `live` 数据；未接入接口时，添加页会明确提示服务尚未接入，不展示假成功。
5. 等待破壳首页、已破壳页面与收藏卡联调需使用 CTO 提供的 `test` 环境和测试账号，不能在生产包内加入本地测试码。

## 当前实现边界

- 本目录只保留前端页面、H5 与 `services/` 接口适配层，不包含云函数，也不调用 `wx.cloud.*`。
- 普通包不注册或实现虚拟资源、商店、背包、随机产出、系列收集、成长百分比与任务能力。
- 内部演示必须使用独立项目、接口、存储和统计；本普通版运行时固定为 `live`，不能切换演示环境。
- H5 收藏卡把分享图数据回传小程序，由微信相册能力保存；开发者工具里建议同时用真机验证授权流程。

## 用户资料与公开 ID

- 普通版前端只展示昵称、头像和服务端用户编号。
- 用户 ID、实体蛋 ID、收藏卡 ID 与身份编号均由服务端生成，前端不随机补造。

## 校验

在项目根目录运行：

```bash
node scripts/verify-project.js
node scripts/verify-v2.js
node scripts/verify-h5.js
node scripts/verify-v211.js
node scripts/verify-egg-shell-art.js
node scripts/verify-home-egg-layout.js
```

校验会检查页面四件套、普通版页面与接口白名单、固定房间小物、真实蛋体、第一人称文案、服务端生命周期、单蛋收藏卡和 H5 确定性渲染。
