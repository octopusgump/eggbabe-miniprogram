# eggbabe 长期收藏卡体系

状态：MVP 最终方案
日期：2026-07-14

## 1. 核心目标

建立一个可以持续扩展多年、身份稳定、编号清晰、发行规则可信的数字收藏卡体系。长期收藏性来自四件事：

1. 稳定且冻结的套装 checklist。
2. 不可混淆的多层编号。
3. 真实且公开的稀缺规则。
4. 可验证的发行记录与版本快照。

MVP 不开发独立道具层，不拆角色、道具和背景，不增加 `FUN FACT`、`STRENGTH`，不人为制造限量版。

## 3. 四层身份模型

### 3.1 套装 Set

定义一个可完成的收藏边界，例如 `YT-S01`。发布后必须保留官方 checklist、发布日期和总卡数。

### 3.2 卡牌定义 Card Definition

定义“这是什么卡”：固定 Hero、卡名、角色原型、卡框主题和清单位置。所有用户抽到的 `yt-s01-007` 都属于同一个卡牌定义。

### 3.3 视觉版本 Treatment

定义同一基础卡的视觉工艺，例如 `BASE`、未来的 `MOONLIGHT` 或 `GOLD-FRAME`。MVP 只有 `BASE`。

视觉版本不得修改卡名、Hero 故事和 checklist 身份。未来上线 parallel 时，必须公开其获得渠道和发行规则。

### 3.4 用户副本 Card Copy

定义某位用户实际获得的一份卡。每份副本有不可复用的 `copy_id`、唯一编号、服务器发行时间和卡面快照。

## 4. 编号体系

四类编号不能混用：

| 类型 | 示例 | 含义 |
|---|---|---|
| 套装代码 | `YT-S01` | 玉兔第一季套装 |
| 清单编号 | `007/010` | 这张基础卡位于十张清单中的第 7 位，不表示稀缺数量 |
| 唯一副本编号 | `EGG-YT-20260714-000137` | 某位用户实际获得的唯一数字副本 |
| 限量序列号 | `037/099` | 只有真实限制该版本总发行量为 99 时才使用 |

`/010` 是套装规模；`/099` 是发行上限，二者含义完全不同。

## 5. MVP 卡面内容

### 固定视觉

- 4:5 Hero 主图：角色 + 固定动作 + 固定道具 + 背景。
- H5 卡框。
- `eggbabe` 品牌字标。
- 套装代码与清单编号，例如 `YT-S01 · 007/010`。

### H5 动态生成

- 用户为角色确定的名字。
- 生日。
- 星座。
- MBTI。
- 唯一副本编号。

### 当前明确不显示

- `FUN FACT`
- `STRENGTH`
- 血型
- 孵化品质
- 初始主人
- 性格长句
- 人为稀有度标签

这些字段即使后台暂时保留，也不得进入 MVP 正面卡面信息区。

## 6. MVP 视觉结构

1. 名字标题区：使用站酷快乐体，名字变更时实时更新。
2. 居中水彩插画：固定 4:5 视口并铺满展示，由服务端按节令 / 性格加权确定，一卡一图固定。
3. H5 信息区：只显示 MBTI、星座和生日；全局编号只进分享图脚注。整卡为 9:16，去除黑色内描边。
4. 卡框和系列标识：由 H5 统一生成，保证十张卡风格一致。
5. 抽卡揭晓效果：遮罩、微光、上浮和轻粒子，仅在交互过程出现，不写入卡面素材。

现有 Hero 不抠图、不拆道具、不叠加独立背景。

## 8. 我的收藏卡和可信度页面

### MVP 必须具备

- 十个固定卡位。
- 已拥有 / 未拥有状态。
- 套装完成度，例如 `7/10`。
- 重复副本数量折叠展示，不用十张相同卡占满卡册。
- 单张卡的唯一副本编号和获得时间。

### 后续建设

- 官方 checklist 页面。
- 单卡验证页：输入或扫描唯一编号验证卡牌定义、版本、发行时间和状态。
- Population 页面：按 card definition 和 treatment 公开发行数量。
- 规则变更记录：概率、发行上限和卡池调整带版本号与生效日期。

数字卡不使用 PSA 式 1–10 品相分；若未来制作实体卡，再建立独立认证与品相体系。

## 9. 长期扩展顺序

1. 验证第一季抽取、收藏完成度、保存和分享。
2. 发布新套装，例如锦鲤 S01、节日套、联名套；每套都有独立 checklist。
3. 用户开始主动追求完整套装后，再测试少量 parallel 视觉版本。
4. 只有真实可封顶、可公开发行量时，才推出 `/99`、`/25` 或 `1/1`。
5. 签名版必须对应真实创作者签署和可验证流程，不使用签名字体假装签名卡。
6. 实体卡立项后再引入印刷批次、品相、封装和第三方认证。

MVP 暂不开发：独立道具层、自由装扮、卡牌交易、付费卡包、复杂 parallel、伪限量编号、数字品相评分。

## 10. 分辨率路线

### 当前版本

继续使用现有约 `850×1070` 的 4:5 Hero，不进行插值放大。当前验证重点是卡面、编号、清单、抽取、保存和分享。

### 下一版本

`1600×2000` 是合理的 4:5 Hero 交付规格：

- 比例与当前 H5 Hero 区匹配。
- 足够支持 1080px 宽分享长图和高密度手机屏幕。
- 统一使用 sRGB。
- JPG 建议高质量导出；如需透明图再使用 PNG/WebP。
- 从原始生成或高分辨率源重新导出，不把本版低分辨率文件简单放大。

### 未来实体卡

`1600×2000` 不是实体印刷母版。实体卡需要另建约 5:7 的正反面模板，并重新规定出血、安全区、CMYK/专色、纸张和 300 DPI 输出；不要让未验证的实体卡需求改变当前 H5 Hero 比例。
