# 静态 3D 玉兔 MVP 复盘与归档

日期：2026-08-06
状态：停止，不进入 V3.6 运行时

## 尝试范围

本次只验证“玉兔、在家、静态坐姿、单一 Pano”的 Three.js 方案：使用 Tripo 导出的 GLB，在破壳后中屏圆垫区域以透明 WebGL 画布叠加；不做骨骼、动作或模型位移，只做轻微灯光变化。

## 结论

渲染链路已验证可运行，但不适合作为当前小程序的角色呈现方案。主要问题不是加载，而是视觉合成：三维模型的材质、光照、比例、朝向、接触阴影与预生成 Pano 不一致；平面全景也无法提供可靠的前景遮挡。即使继续调参，首期投入产出不成立。

因此，V3.6 恢复为透明 WebP 角色姿态叠加在既有 Pano 上的方案。3D 不再出现在运行时代码、页面组件、配置或小程序 npm 依赖中。

## 后续 2D 生图方案调整：角色与场景一起生成整张 Pano

透明 WebP 叠加样张已完成验证，但视觉验收不通过：它与原 Pano 的暖色、透视、接触阴影、前后遮挡和纸张关系无法稳定融合。与已停止的 Three.js 方案相同，问题属于“后合成”，不值得继续细调。

后续正式方案改为：以对应的空房间 Pano 为严格构图参考，连同玉兔和固定动作一次性生成新的 `2823 × 1672` 三屏连续全景图。角色、场景、光照、投影和遮挡在同一张图中烘焙完成；运行时只切换已审核的整图，不再叠加透明角色层。

外出时仍旧显示空着的家和第一人称文字。当前透明 `stare_sunset_v01.webp` 仅保留为方案比对样张，不作为后续正式美术方向。

| 居家固定状态 | 所在屏 | 最小新增整图 | 说明 |
| --- | --- | --- | --- |
| 睡觉 `sleep` | 左屏 | 1 张 / 环境 | 侧趴 / 蜷睡，含与床铺一致的接触阴影 |
| 发呆 `stare` | 中屏 | 1 张 / 环境 | 坐地、轻歪头，作为默认可对话状态 |
| 慵懒 `lazy` | 左或中屏 | 1 张 / 环境 | 放松坐姿或趴姿，需与睡觉明显不同 |
| 画画 `drawing` | 中屏 | 1 张 / 环境 | 玉兔、纸笔与遮挡关系一次生成 |
| 游戏 `gaming` | 中屏 | 1 张 / 环境 | 玉兔与小屏幕 / 手柄一次生成 |
| 看窗 `window` | 右屏 | 1 张 / 环境 | 背影或三分之二背影，面向窗户 |

**结论：透明角色图最小集不再作为正式交付口径。** 每一张通过审核的“状态 × 环境”产物都是完整 Pano；不得把同一角色图复用于光线不同的 Pano，也不得把角色从一张图扣出后重新合成到另一张图。

首个验证资产建议只做 1 张：`玉兔 + 在家发呆 + 中屏圆垫 + 指定日落 Pano`。通过后再决定按“7 个居家状态 × 3 个时段 = 21 张”逐步扩展，或按更严格的状态 × 全部 36 个环境扩展。外出状态图仍为 0 张，骨骼动画仍为 0 个。
