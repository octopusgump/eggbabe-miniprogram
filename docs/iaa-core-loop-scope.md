# IAA 四项核心闭环｜开发验收范围

> 状态：开发态范围收敛（2026-09-20）
> 边界：`LOCAL FIXTURE` / `NO BACKEND` / 不代表已合入 `main`

## 保留的唯一主循环

`今日陪伴 → 陪伴星星 → 明日提示 → 极简纪念册`

| 顺序 | 保留项 | 在闭环中的作用 |
| --- | --- | --- |
| 1 | 今日陪伴 | 呈现当日内容，承接一次轻量陪伴 |
| 2 | 陪伴星星 | 位于房间左上角“今日心情”状态区；有效陪伴后 `+1`，同日不重复增加 |
| 3 | 明日提示 | 初次进入今日陪伴页即可看到“明天呢？”，点击后展开次日线索；不使用倒计时或断签惩罚 |
| 4 | 极简纪念册 | 保存已解锁的纪念，作为陪伴的留存结果 |

## 纪念册的最小范围

- 保留纪念列表和空状态。
- 单条纪念只需要图片、标题、日期和一句话。
- `app.json` 只注册纪念册列表路由，不再注册独立纪念详情和保存卡路由。
- 不在本验收台展示稀有度、未解锁卡墙、分享导出或复杂动效。

## 删除或不引入

- 奖励揭晓。
- 广告状态与广告 adapter。
- 独立合规验收页。
- 纪念详情页和纪念保存卡的编译路由。
- 独立陪伴星星页；星星只作为房间常驻状态出现。
- 独立明日提示页；入口与线索都留在今日陪伴页内。

原有 AI 身份提示、协议与隐私政策入口、健康提醒不在本次删减范围内。不单独展示合规验收页，不等于取消现有合规要求。

## 用户视角页面定稿约束

以下规则来自本轮人工验收，后续修改必须直接遵守，不再进行未经确认的“补充设计”。

### 1. 用户确认的内容是封闭清单

今日陪伴信纸只允许出现：

- 标题；
- 当日一句话；
- 陪伴操作文案；
- 完成后的原有场景反馈与 `+1`；
- 初始可见的“明天呢？”；
- 点击后展开的一句明日内容。

不主动增加小标题、落款、状态说明、完成文案、星星去向说明、图标、勾选符号、徽章或解释性文字。用户没有提出的可见元素，默认不加入。

### 2. 只保留两级内容文字

- 唯一标题：`42rpx / 1.3`。
- 其余用户内容：`27rpx / 1.55`。
- 照片上的日期与当日类型也属于正文层级，不得与标题争抢视觉重量。
- 开发验收信息不属于用户内容，必须与用户页面隔离。

### 3. 装饰不能替代信息结构

- 不使用心形、完成勾或圆形按钮装饰陪伴操作。
- 不在陪伴操作上下添加分隔横线。
- 信纸不添加装饰横线；纸张质感只保留背景、折角和已确认的竖向页边线。
- “明天呢？”保留下划线，因为它承担点击提示；不再增加其他提示符号。

### 4. 初始态必须让后续能力可发现

- 页面初次展示时，同时看得到陪伴操作和“明天呢？”。
- “明天呢？”不依赖先完成陪伴，点击即可展开明日内容。
- 曝光在入口初次可见时记录，展开在用户点击时记录，不上传正文内容。

### 5. 每次排版修改必须覆盖完整状态

修改字号、行高、间距或点击行高度时，必须同时检查：

- 初次进入；
- 完成陪伴后；
- 明日内容展开后；
- 四种内容场景；
- 加载、空态与失败态。

不能只修当前截图。尤其调整 leading 时，要一起核对 `line-height`、`min-height`、`margin`、`padding` 和展开态覆盖规则，避免默认态正确、展开态再次错位。

### 6. 修改纪律

- 一次只改用户指出的问题，不顺手增加替代元素。
- 视觉好坏由用户人工确认；用户未要求时，不用 computer-use 代替人工验收。
- 自动测试只证明结构和状态没有回归，不代表视觉已经获得用户确认。
- 未经用户确认，不合并到 `refactor/iaa-core-loop-scope-20260920` 或 `main`。
