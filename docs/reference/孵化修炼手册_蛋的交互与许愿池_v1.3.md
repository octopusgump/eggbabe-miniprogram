## 1 · 任务感表达规范（本版核心约束）

孵化修炼手册在机制上是"每天做几件小事"，但在体验上必须是"每天来看看 ta"。这一节定义两者的分界线，开发与设计按此执行，QA 按 §1.6 逐条验收。

### 1.1 两个术语的定义

| 术语 | 定义 |
|---|---|
| **每日有效次数** | 系统对同一动作在自然日内的可计次数，**以及把这个次数暴露给用户的任何表达** |
| **当日进度** | 把当天多个动作的完成情况**汇总成一个可度量的状态**并展示给用户 |

v2.28 禁的是**暴露与汇总**这一层，不是后端的次数约束本身。后端该有的约束照留。

### 1.2 总原则

> **单项状态可见，汇总度量不可见。**

用户可以知道"今天这件事我做过了"，不能知道"今天做了几件、还剩几件、完成了百分之多少"。

### 1.3 后端保留（机制层，必须实现）

- 每个动作按 `(egg_id, action, server_date)` 建唯一约束，服务端北京时间 UTC+8 为唯一权威时间源；
- 重复提交返回 `already_done`，**不再重复减时**；
- 减时以分钟为单位累计写入蛋的孵化记录；
- 一次性动作（起昵称、彩蛋涂鸦）按 `(egg_id, action)` 唯一，全周期只减一次。

### 1.4 前端规范

**❌ 禁止清单**

| 类别 | 禁止出现 | 具体例子 |
|---|---|---|
| 次数 | 任何剩余 / 已用次数 | "今日剩余 1 次""本次不计入""已用 1/1""今天还能许一次愿" |
| 进度 | 任何汇总度量 | 进度条、百分比、环形进度、"今日 2/5""已完成 3 项" |
| 完成态汇总 | 把当天各动作拉成一个清单再标状态 | ✅ 勾选、"已完成"角标、完成项灰置或置底排序 |
| 催促 | 任何提醒未完成的表达 | 红点、角标数字、"还差一步""今天还没摸过我""别忘了…" |
| 连续 | 任何跨日累计 | "连续第 5 天""打卡日历""连续中断了" |
| 累计减时 | 减时的总量表达 | "累计缩短 12 小时""距离破壳还差 3 步" |

**✅ 允许清单**

| 项 | 说明 |
|---|---|
| 今天的题目本身 | 换题就是"今天不一样"的全部信号，不需要额外提示 |
| 单次即时反馈 | 提交后一段动画 + 一句第一人称文案 |
| 单项已做状态 | 当天再次进入该动作，直接展示用户今天的选择（如"今天你许过愿啦 —— 🌙 月光牛奶浴"），**不用"已完成"字样、不打勾、不灰置** |
| 预计破壳时间 | 首页常驻展示绝对时间（如"预计 8 月 2 日破壳"），减时后这个时间自然往前走 |
| 单次减时反馈 | 提交瞬间可给一句轻表达，如"蛋宝宝好像近了一点点"，**不给累计值** |

### 1.5 减时的可感知方式（关键设计）

减时必须能被感觉到，否则动作没有动机；但"还差多少"一旦被显示出来就变回进度条。分界线是：

> **展示绝对的破壳时间，不展示相对的剩余量。**

「预计 8 月 2 日破壳」是一条事实陈述，用户第二天看到它变成「8 月 1 日」，自己就知道发生了什么。「还剩 123 小时」「已缩短 23%」则是进度表达，禁止。

### 1.6 QA 验收清单

- [ ] 全站搜索无"完成""进度""剩余""次数""连续""打卡"等词出现在修炼手册相关页面
- [ ] 修炼手册页无进度条、无百分比、无勾选控件
- [ ] 当日重复提交：接口返回 `already_done`，孵化记录未二次减时
- [ ] 当日重复进入某动作：展示本人今日选择，无次数、无完成角标
- [ ] 修炼手册入口与底部 tab 无红点、无角标数字
- [ ] 跨日凌晨 00:00（北京时间）题目切换正确，前一日答案不被覆盖
- [ ] 首页只出现"预计破壳时间"绝对值，无剩余时长、无缩短总量
- [ ] 未做任何动作的用户，全程收不到任何催促文案或订阅提醒

| 彩蛋涂鸦 | 12 小时 | 一次性 | 交互型 | 选颜色、图样，生成蛋壳表面纹理 |

### 2.1 ⚠️ 减时上限模型（待定，建议本周定）

按上表算，减时能力是：**一次性 −24 小时**，加上**每日最多 −3 小时**。

| 破壳周期 | 原时长 | 全勤减免后 | 实际缩短 |
|---|---|---|---|
| 7 天（MVP 默认） | 168h | 约 129h ≈ 5.4 天 | −23% |
| 10 天 | 240h | 约 195h ≈ 8.1 天 | −19% |
| **3 天（短周期）** | 72h | **约 42h ≈ 1.75 天** | **−42%** |

3 天档的减时比例明显失控——一次性的 24 小时在短周期上占比太大，用户第一天就能把三分之一的等待砍掉，反而削弱了等待本身的价值。

**建议二选一：**

- **方案甲（推荐）**：设孵化时长下限 = 原时长 × 60%，减到下限就停，界面不做任何提示，用户只是看到预计破壳时间不再往前走；
- **方案乙**：一次性动作的减时按周期比例缩放（7 天档 −12h，3 天档 −5h），每日动作维持 −1h。

方案甲实现简单、对短周期最安全；方案乙更精细但配置项变多。**待你定。**

## 3 · 蛋的交互（5.2.3）

### 3.1 定位与和修炼手册的关系

蛋的交互发生在**破壳前的小程序主界面**，是用户打开小程序看到的第一件事，也是停留时间最长的地方。

它和修炼手册是**半重叠**的关系：

| | 归属 | 说明 |
|---|---|---|
| 当天**第一次**点蛋 | 属于修炼手册 | 自动完成「摸一摸」，−1 小时 |
| 当天**之后每一次**点蛋 | 不属于修炼手册 | 不限次数，只有摇晃、震动和文案，不减时 |

**建议采用这个模型**：用户不需要专门进修炼手册去点"摸一摸"，摸这个动作发生在主界面上，是自然的；手册里的「摸一摸」只作为一个入口存在，点进去也是回到主界面摸蛋。

> **待确认**：是否接受"主界面第一次点蛋即完成摸一摸"。若坚持在手册内单独完成，则主界面点蛋全程不减时，两者完全分离。

按 §1 的规范，无论采用哪种，主界面都**不出现**"今天已摸""还能摸 X 次"这类表达。

### 3.2 交互 1 · 触摸点击

| 项 | 规则 |
|---|---|
| 触发 | 点击蛋体任意位置 |
| 蛋体动作 | 左右轻微摇晃 + 压缩回弹，幅度克制，不夸张 |
| 视觉 | 点击处出现短暂星点，同屏粒子不超过 3 组 |
| 震动 | `wx.vibrateShort()` 轻震一次 |
| 震动节流 | 两次震动最短间隔 300ms，连点不叠加、不连震 |
| 系统关闭震动 | 静默跳过，不提示、不报错 |
| 弱动效模式 | 降级为单颗星点淡出，不摇晃 |
| 禁止 | 不出现"+1"、到账动效、进度、"再点一次"等提示 |

### 3.3 交互 2 · 随机文案

| 项 | 规则 |
|---|---|
| 触发 | 与交互 1 同时触发 |
| 展示 | 蛋体上方轻量气泡，2 秒内最多显示 1 条 |
| 取词 | 从下方文案池随机取一条，**连续 5 条内不重复** |
| 条件过滤 | 先按当前昼夜、天气、临近破壳状态过滤出可用子池，再随机 |
| 第一人称 | 自称"我"，称用户"你"，不用第三人称旁白 |
| 禁止方向 | 不催促、不索取、不责备、不表现饥饿或被抛弃、不提任务或解锁、不鼓励情感依赖或排他关系 |

## 5 · 交互 3 · 破壳分享卡片

### 5.1 现状与待确认

破壳时生成一张可保存、可分享的卡片，沿用**已有的水墨画风格卡面**。

⚠️ **命名与范围需要先对齐**：PRD v2.28 §9 已经有一个「收藏卡」，同样是一蛋一份、破壳时生成、H5 渲染、可保存可分享。**「破壳分享卡片」和 §9 收藏卡是不是同一个东西？**

- 若**是同一个**：本节只做卡面风格的补充说明（水墨画风格），其余字段、编号、生成规则全部引用 §9，不重复定义，也不重复开发；
- 若**是两个**：需要说明两者的差异（触发时机、字段、是否入收藏页），否则开发会做出两套卡。

**建议是同一个。** 目前没有看到需要两张卡的理由，收藏和分享本来就是同一张卡的两种用法。

### 5.2 若确认为同一个，本节补充如下

| 项 | 内容 |
|---|---|
| 卡面风格 | 沿用现有水墨画风格卡面，不新建视觉体系 |
| 生成时机 | 破壳完成后一次性生成，幂等 |
| 字段 | 引用 PRD §9.3，不在本文重复 |

## 8 · 蛋蛋早教班（5.2.2）

### 8.1 定位

强化用户与宠物之间的日常交互。用户每天教蛋宝宝一件小事，看到 ta 学会的样子。

### 8.2 规则

- **单选**，每日可互动提交一次；
- **固定选项**：选项不每日更新，与许愿池的每日换题形成区分；
- **提交后播放一段动画**即完成，无评分、无对错、无学习进度；
- **减时**：首次成功提交 −1 小时；
- **本期不影响性格**：答案落库但不参与性格生成、不参与破壳收藏卡字段、不参与对话上下文；
- 与许愿池共用「每日一次」的后端约束逻辑，但**独立计数**，两者互不占用；
- 前端表现严格遵守 §1。

### 8.3 选项与动画清单（草案，待你定版）

每个选项需要一段独立的短动画，建议时长 1.5–2.5 秒，可复用蛋体呼吸与光泽基座。

| 选项 ID | 选项 | 动画方向 |
|---|---|---|
| EDU-A | 👋 学会打招呼 | 蛋体左右轻晃两下，壳面短暂发光 |
| EDU-B | 🙏 学会说谢谢 | 蛋体向前轻点一下，像鞠躬 |
| EDU-C | 😴 学会好好睡觉 | 壳面光泽渐暗，呼吸幅度变缓，冒一个小气泡 |
| EDU-D | 🫧 学会自己洗澡 | 壳面泛起一层水光，几个泡泡升起消失 |
| EDU-E | 🤝 学会分享 | 蛋体轻轻向一侧倾，像把东西递出去 |
| EDU-F | 🎵 学会哼歌 | 壳面随节奏做两次微幅缩放，冒出音符 |

> 六个选项对应六段动画，是本模块最大的资产成本项。若要压首版工作量，可先上 A / C / F 三个，其余灰置为"下次再教"。

## 9 · 数据结构与偏好映射

### 9.1 落库结构

```json
{
  "record_id": "uuid",
  "egg_id": "string",
  "user_id": "string",
  "module": "wish_pool | edu_class | touch",
  "question_id": "WP-N02",
```

- 唯一索引：`(egg_id, module, server_date)`；
