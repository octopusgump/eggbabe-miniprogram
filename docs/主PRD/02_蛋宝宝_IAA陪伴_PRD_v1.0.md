## 1. 产品概述

让用户与宠物完成一件小事，得到明确反馈，留下回忆，并期待下一次相处。核心闭环为：**今日陪伴 → 获得星星 → 明日期待 → 纪念册 → 下一次共同活动**。体验保持简单，不做复杂养成面板、排名或充值系统。

| 概念 | 用户看到的内容 | 含义 |
|---|---|---|
| 星星 | 可用余额 | 陪伴获得，可兑换纪念内容或参加活动；不涉及人民币充值 |
| 一起 X 天 | 累计连续有效陪伴日数 | 当日首次**点开信纸**（信封→信纸可见）即 +1；是否完成信内动作不影响；只开信不做动作则 **+1 天、0 星**；茶会等动作**不**因完成而单独 +1；**自然日未开信则断开清零**，次日从 1 重新累计；消费不减少星星余额 |
| 回忆 | 照片、真实作品 | 已留下的共同经历 |
| 活动 | 可参与的小事 | 用户实际付出选择或创作，获得对应结果 |
| 明天呢？ | 下一次相处的线索 | 不是领取奖励，也不是聊天文字入口 |

## 3. 主流程

1. 进入房间：左上显示星星余额与“一起 X 天”；左下信件入口出现轻量到信提示。
2. 用户点击信封读信，了解宠物今日的小事；没有自动展开的信件弹窗。
3. 用户完成核心动作：普通日做一次选择；**特别奖励**日须完成对应流程——信内「一起画」并导出，或如窗边茶会等多步活动；外出日回应纸条。
4. 在动作对应的结算点展示星星和宠物回应。用户可以继续玩，但同类每日额度不重复发放。
5. 用户主动点击“明天呢？”，查看后续线索。在家时角色出现，点击角色进入完整聊天。
6. 有照片或作品时点击“收下”加入纪念册；收藏不决定星星是否发放。
7. 从百宝箱进入纪念册，在“回忆 / 活动”之间切换，继续查看回忆或参加活动。

### 3.0 今日信件事件三类（互斥）

2026-10-09（北京时间）COO 修订：原「共同创作」「特别活动」不再与「日常陪伴」「外出牵挂」并列成四类，统一并入 **特别奖励（reward）**。以下分类**只描述今日信件指派的核心动作**；同一封信仅属一类。A 类兑换、随机惊喜、明天呢、收下**不参与**此分类。

| 类 | 定义 | 当前实例 |
|---|---|---|
| **日常陪伴** | 宠物在家；信内**一次选择或一次简短互动**；不是画板导出，也不是 B 类多步活动流程 | 普通在家信 |
| **外出牵挂** | 宠物**外出**；信内核心为**纸条 / 牵挂**（不能进聊天；明日呢无角色） | 替它收好纸条 |
| **特别奖励（reward）** | 信内核心**不是**「一次点击即结束」：须走独立流程并取得明确结果 | 信内「一起画」（§6）；或窗边茶会（§7.3）及已确认方向的轻答题、旅行（§7.4）等多步活动 |

**特别奖励**下「一起画」与「多步活动」（如茶会）**同一自然日只能占一种**为今日信核心；结算仍各走 §5、§6、§7，不因合并口径而混算。用户可在非今日信核心时自行打开纪念册「活动」页（如兑换照片、续茶会进度），**不改变**当日信件三类标签。

随机惊喜是事件内的额外反馈，不另建与上述三类并列的分类。

**废止口径（2026-10-09）**：对外与文档不得再使用「事件四类」「共同创作与特别活动并列成类」。历史归档（如 Q46）保留追溯；现行以本节为准。

**判据（同一封信只问一次，命中即停止）**：

1. 宠物外出且信内核心为纸条/牵挂 → **外出牵挂**
2. 否则，信内核心为**一起画**（须成功导出）→ **特别奖励**
3. 否则，信内核心为**多步活动**（如茶会）→ **特别奖励**
4. 否则（在家、一次选择或短互动）→ **日常陪伴**

**不参与上述判据**：纪念册「活动」页的 A 类兑换、用户自开茶会/续进度（不改变当日信件类标签）、随机惊喜、明天呢、收下。

### 3.1 单个陪伴事件的玩法闭环

2026-10-04（北京时间）COO 确认：**事情发生 → 用户参与 → 宠物回应 → 获得结果 → 后续延续**。

**陪伴事件**指用户与宠物围绕**一件具体小事**形成的一次共同经历。今日信件（§3.0）指派的是当日**核心**陪伴事件；纪念册「活动」页的自开流程（如续茶会、兑换照片）是**另一条**活动线，不改变当日信件类标签，但若走完整参与—回应—结果链，仍应按同一闭环设计内容。

设计或评审任何一个陪伴事件时，必须能逐项写清下面五段；缺一段则不算事件定义完成（实现与文案可分批交付，但产品表不可留空）。

| 闭环段 | 设计时要回答的问题 | 边界说明 |
|---|---|---|
| **事情发生** | 用户打开信纸时，房间里/信里**已经呈现**的情境是什么？宠物处于什么状态（在家／外出）？ | 只描述「小事已发生」的可见设定，不是系统后台状态名。到信提示、开信本身不替代「事情发生」的文案与画面。 |
| **用户参与** | 用户为完成这件小事要做的**核心动作**是什么（一次选择、多步确认、创作导出、收纸条等）？ | 与 §3.0 判据一致：日常陪伴 = 一次选择或短互动；特别奖励 = 独立流程；外出牵挂 = 纸条／牵挂。不含「明天呢？」、纯阅读、收藏「收下」（收下是结果入库动作，见下）。 |
| **宠物回应** | 参与后（或参与过程中）宠物给出的**对白／信内反馈**是什么？选择不同是否换回应？ | 至少改变**当次**回应（§3.2）；不承诺每句回应都接入模型或长期记忆。 |
| **获得结果** | 用户当场拿到的**可感知收益**是什么？ | 通常包括：星星（按 §5.2 结算点）、可预览／收下的照片或作品、活动内明确结果（如茶会照片）。**随机惊喜**（§7.5）是在**本段基础结果已保证**之上的额外回礼，不替代基础结果。基础结果未达成（如导出失败、照片加载失败）时不应假装完成闭环。 |
| **后续延续** | 这次小事如何连到**下一次相处**或**共同回忆**？ | **设计方向**，分三档即可，不要求每事件都做到最高档：**① 当次收束**（回应结束，无跨日承诺）；**② 线索型**（「明天呢？」、信末暗示、纪念册待收下）；**③ 跨日型**（后续房间出现作品、下封信引用上次选择等，§4.4 目标）。不要求每次事件立即产出跨日内容；**不表示**真实记忆、模型或用户画像已接入（§2、§8）。 |

**事件定义表（模板）**：每一种玩法（一封信里的核心小事、或纪念册里一项花星活动）占表格一行，五列与上表同名。若该玩法还有「额外小惊喜」，写在同一行「获得结果」里，注明「平时给什么 + 偶尔额外给什么」，不要拆成两个事件，也不要和 §3.0 信件三类并列成新类别。

**已确认实例（五段对照，规则细节见引用章节）**：

| 事件（示例） | 事情发生 | 用户参与 | 宠物回应 | 获得结果（基础） | 后续延续 |
|---|---|---|---|---|---|
| 外出牵挂 · 收纸条 | 房间留纸条，宠物外出 | 替它收好纸条 | 如：你把纸条压在杯子旁边，等它回来 | 普通核心动作对应的基础星星（§5.2）；正常纸条对白 | 「明天呢？」外出无聊天角色（§4.4）；纸条照片机制为额外惊喜（§7.5.2），非每日保证 |
| 特别奖励 · 一起画 | 信内邀请一起画 | 打开画板 → 创作 →「画好了」成功导出 | 完成短句（§7.5.1 轮换）；不评画 | 画布就绪发当日基础（若额度未用）；导出成功发画画额外（各 §5.2）；作品在信纸展示 | 用户「收下」进纪念册；明日线索可延续共同活动（§4.4）；画画小回礼为额外星，不改变基础结果 |
| 特别奖励 · 窗边茶会（信内核心或活动页） | 邀请窗边喝茶 | 选茶 → 确认完成（资源就绪后结算） | 清茶／花茶各一句短回应 | 窗边照片 + 文案；**不发**普通基础星（§7.3） | 收下进回忆；可付费再开；茶会额外照片方向见 §7.5（待齐规则） |
| 日常陪伴 · 普通在家信 | 宠物在家，信里一件小事 | **一次**选择或短互动 | 随选择变化的当次回应 | 完成核心动作发当日基础星一次（§5.2） | 多为线索型「明天呢？」；是否改变回忆因事件而定（§3.2） |

日常陪伴的具体情境库由内容维护逐项填表扩充；上表仅固定已交付或已锁规则的链路，不授权未定义数值或新结算。

每个事件都需要定义具体发生了什么、用户参与的动作、宠物对应的回应、用户获得的结果，以及可延续的共同经历。后续延续是事件设计的方向，不要求每次事件立即产生跨日内容，也不代表真实记忆服务已经接入。

### 3.2 事件内容如何持续扩充

2026-10-04（北京时间）COO 确认以下原则：

- 内容变化与新操作玩法都需要，以内容变化为主，逐步增加新玩法。例如沿用画板，分别围绕画云、画树等具体小事设计情境与回应；之后再扩充轻答题、旅行准备等操作。
- 用户的选择至少改变当次回应；部分事件进一步改变留下的回忆或后续小事。不要求每个事件都改变最终回忆，不重新定义已确认的画画及茶会流程。
- 新事件逐个定义并持续扩充，作为核心玩法内容维护；随机惊喜附着在具体事件中，在原有基础结果之上增加获得感。

持续扩充事件内容是产品方向，内容由谁制作、如何供给、如何选择与避免重复仍待确认；当前不授权接入远程模型、用户画像或真实记忆服务。

## 4. 房间与信件交互

### 4.1 房间入口

- 左上：星星余额、“一起 X 天”；不展示独立宠物心情入口。保留现有时钟。
- 左下：圆形信封按钮。在家与外出均使用该入口。未读有小红点，实际打开信件即消失，不能要求先完成活动。
- 右下：保留齿轮设置按钮；其上放百宝箱。百宝箱打开小图标弹窗，第一个功能是“纪念册”。
- 首次得到可收藏回忆时，轻量引导用户打开百宝箱并找到纪念册，不增加强制多步教学。

### 4.2 到信提示

北京时间每天首次进入房间，纸飞机只在左下圆形按钮内部轻微变成信封，约一秒。禁止横穿房间、大幅飞行或夸张转场。

搭配已选定的短促、柔和“嗖”音效：约 0.28 秒，低音量，遵循系统静音。提示结束停在信封状态，等待用户点击；当天关闭重开不重复播放。音效无法播放不阻塞读信。

### 4.3 信纸

居中浮层，周围仍能看到房间；关闭按钮清晰，点击遮罩可关闭。信纸展示今日内容、核心动作、回应和“明天呢？”。心情可融入信件或在家对白，不另加仪表。

**不再出现“陪伴 / 聊天”分栏，也不出现“进入聊天”文字按钮。** 信件不写入完整聊天记录。

外出示例：

> 房间里留着一张小纸条。
>
> “我去看看风把叶子吹到了哪里，晚一点回来。”
>
> 操作：替它收好纸条。
>
> 回应：你把纸条压在杯子旁边，等它回来。

该示例是当前模拟内容，不代表每日内容生成已经接入。

### 4.4 明日期待与聊天

- “明天呢？”在活动前后都可点击；点击不发星，不增加陪伴日数，完成活动不自动展开它。
- 在家：展开明日内容，当前宠物从信纸右下边缘向上探出，约一秒淡入上移后静止。使用透明静态图，不使用循环 GIF。
- 角色为用户实际宠物：玉兔或锦鲤；不存在给用户切换宠物的控制按钮。
- 点击角色进入现有完整聊天页。动画期间也可点击；重复点击只触发一次导航。
- 外出：只展示明日内容，不展示可聊天角色，不能进入聊天。
- 在家但已有聊天限制时，角色仍可见；点击说明现有限制并保留信纸。
- 当天关闭重开或从聊天返回，保留明日展开状态与角色，不重播入场。次日重置当日提示状态。

明日内容优先延续共同活动、用户明确兴趣和主动愿望。私人困扰是否再次提起由用户选择，不能默认把每次聊天变成次日提醒。作品在后续房间中对应出现是已确认目标，当前前端未完成这条内容链路。

## 5. 星星与累计陪伴规则

### 5.1 基础收益阶梯

按**累计连续有效陪伴日数**确定当天基础星星；当天首次结算时冻结基数，后续同日结算不再变化。

| 累计连续有效陪伴日数 | 当日基础星星 |
|---|---:|
| 1–2 | 10 |
| 3–6 | 11 |
| 7–13 | 12 |
| 14–20 | 13 |
| 21–29 | 14 |
| 30–44 | 15 |
| 45–59 | 16 |
| 60–89 | 17 |
| 90 及以上 | 18 |

陪伴「一起画」**只**从今日信进入（§6.1）。点开信纸后「一起 X 天」已含今天；当日首次发星结算按「含今天」的连续日查表并冻结。例如已连续两天，今天已开信后再进画画，开始奖励为 11 星；画好后再得 11 星（同日冻结基数不变）。

不自动生息，不按余额计算收益，不做多种倍率。历史小数星星、旧成长标签和旧收益方案由本表覆盖。

#### 5.1.1 已确认：开信加天数、断开清零（2026-10-09）

1. **「一起 X 天」何时 +1**：当日首次**点开信纸**（信封→信纸可见）即记为当日有效陪伴；是否完成信内核心动作**不影响**（每日最多 +1）。只开信、不做普通选择／画画／茶会 → **+1 天、0 星**。
2. **基础星星**：本节阶梯表只定义「基础星星」档位；完成画一画等任务在 §5.2 **另行**发放与基础档位相关的星星（如「画好了」额外一份冻结基数），不改变本节查表含义。开信本身不发星。
3. **断开清零**：若中间有自然日未开信（未记有效陪伴），**连续计数清零**——「一起 X 天」展示与 §5.1 阶梯查表均从第 1 天 / 第 1 档重新累计（废止「间断／断开不清零」）；消费星星只减余额，不追回已发星星。
4. **茶会与天数**：茶会成功完成**绝不**使「一起 X 天」+1；天数**只**由开信纸触发。从纪念册自开茶会亦不加天数。

实现备注：本地 mock（`iaa-star-unlock-adapter`）已按本节：开信纸记天、任务只发星、断天清零、茶会不加天；仍为运行内演示，**不等于**真实账户持久化。
### 5.2 结算点与额度

| 动作 | 星星 | 「一起 X 天」 |
|---|---|---|
| 当日首次点开信纸（信封→信纸可见） | 不发 | 当天 +1（见 §5.1.1） |
| 关闭信件、点击“明天呢？” | 不发 | 不增加 |
| 完成普通核心动作 | 当日基础奖励，最多一次 | 不增加 |
| 主动点击“一起画”，画画页及画布成功就绪 | 当日基础奖励，与普通动作共用一次额度 | 不增加 |
| 有真实笔迹，点击“画好了”，作品成功导出 | 当日首次画画完成额外奖励，等于冻结基数 | 不增加 |
| 重复进入或再次完成画画 | 不重复发上述奖励 | 不增加 |
| 收下已完成作品 | 不额外发星 | 不增加 |
| 成功确认完成茶会，产生照片结果 | 不发星，不领取普通基础奖励 | **不增加**（永不因茶会 +1） |

一天常规最多获得**两份基数**：① 与普通核心动作**共用**的「当日基础奖励」一份；② 当日**首次**「画好了」并成功导出时的「画画额外奖励」一份（各等于当天**冻结基数**，见 §5.1）。两份相加的理论封顶为 **36 星**（例如冻结基数为 18 时 18+18）。

**不计入上述 36 星封顶的额外星**：§7.5.1 画画小回礼（固定 +3）、纸条照片等其它已定随机惊喜中的加星；它们不改变 §5.2 两份基数额度，也不替代基础结果。

用户先完成普通动作再画画，进入画画不再发第一份基础，完成作品仍可取得当日画画额外奖励。

「一起 X 天」按 Asia/Shanghai 自然日计算，每日最多因开信 +1；**未开信的自然日视为断开，次日清零重计**（见 §5.1.1），不补签。星星消费只减少余额，不追回已发星星。

前七个有效陪伴日（均已开信）每天均领取普通或画画基础奖励时，基础收益共 76 星；每天均首次画好则再得 76 星。若某日已开信但只完成茶会、未领取普通／画画基础奖，则该日不计入上述基础星收入。茶会 20 星与旅行 40 星共 60 星，七个有效日的基础收入可覆盖，剩余 16 星。不把“七个有效日”写成无条件七个日历日。

### 5.3 星星反馈

结算后在信纸上方展示真实“+X”与约 2 秒的大星挤压弹出动效，不新开奖励窗口。不使用装饰星飞向左上余额；关闭信件后左上角余额数字更新并做轻量回应，不重播收星挤压与声震。信纸内装饰光点数量不表示实际收入。关闭重开不重复发奖或重播。

系统减少动态效果时使用静态反馈，不播放飞行动画或震动；静音不影响数值结算。模型回应不能自行承诺业务规则外的奖励。

## 6. 一起画

破壳后新增共同画画流程，复用孵化前“画一画”的布局和工具，包括蛋形画布、画笔、橡皮、贴纸、撤销与清空；完成按钮为“画好了”。不改变孵化前原有保存流程，不把陪伴作品保存成宠物蛋壳。

### 6.0 读者说明（通俗）

本节用日常说法概括 §6.2 与 §6.4 已定、但**可能尚未上线**的规则；细节与验收以各小节正文为准。

**画好了怎样才算数**

- **现在（v1）**：至少有一笔真实画笔迹（不是只有贴纸或橡皮），点「画好了」并成功导出即可。
- **将上线（v2，未实现）**：除有真实笔迹外，还要**同时**满足：至少 **5** 笔、有效作画至少 **15** 秒、画布大约 **5%** 的面积被画到。不够时**不能**完成，只轻轻提示「**再画一会儿，让我看得清楚一点。**」；画面上**不**显示进度条或「还差几笔」。

**道具简笔挑战日 · 六步主链（例如拨浪鼓，未实现）**

> **新流程（COO）**：步骤 **4–5** 在**回信纸**展示**道具**、**收下**与**星**；**不是**「第 3 次才在画板出道具」。有人一次「画好了」就通过，**没必要**为道具再画其余两次。

只在**今天信里是一起画**，且这次绑定了**某个道具**时出现；不是每天都有的常驻玩法。

| 步 | 用户侧 |
|---|---|
| 1 | 信件邀请；当日**尚未领取**的基础奖励仍可在进画板时发放（§6.1） |
| 2 | 点「一起画」→ 蛋形画板打开 → 开始作画（看一看流程见下） |
| 3 | 线框简笔约 **5** 秒 **flip** 收回；共 **3** 次「看一看」（与作画次数无关）；点「画好了」须过 **§6.2 v2 三门** 并成功导出 |
| 4 | **回信纸**：本次**作品** + **宠物回应** + 道具**真实形态**（如拨浪鼓）+ **「收下」**（不加方形卡片底板） |
| 5 | 点「收下」：**道具先入**纪念册 **「回忆·道具」**；星星仍只走 §5.2（当日首次画画额外，**一次**）与 §7.5.1（当日首次小回礼 **+3**，**一次**）；**不**因道具另加天、不另开经济线、不扣星 |
| 6 | 收下完成 → **回房间**（§6.1 首次收藏可引导纪念册） |

**画板上的「看一看」（仅步骤 2–3，不是「第三次才出道具」）**

- 蛋形画布上会出现道具的**线框简笔**（不是照片，也没有单独预览页）。上方显示「**还有 X 次机会看一看**」——**X = 还能再看几次简笔**，**不是**作画次数、**不是**「第几次画好了才出道具」。
- 简笔展示期间**不能画**；flip 消失后才作画。共 **3** 次看一看：首次自动；**X>0** 时可点「**再看一眼**」。

**废止（勿再写进验收）**：**累计 3 次**达标导出才在**画板**上展现道具；过关后强制再画两轮仅为了入册。

**不做的事**：不评「画得像不像」、不用 AI 看图、不弹完成度百分比。

**和代码的关系**：v2 门槛与 §6.4 道具挑战已在本文定稿；小程序 mock／正式实现**另开任务**。在上线前，验收仍按 v1（且无道具简笔流程）执行。

### 6.1 正常流程

信件邀请 → 用户点击“一起画” → 画布成功打开 → 发当日尚未领取的基础奖励 → 用户创作 → 点击“画好了” → 导出成功 → 发当天首次画画额外奖励（「一起 X 天」见 §5.2 开信纸，画画本身不加天数） → 回信纸展示作品与宠物回应 → 点击“收下”收藏。

作品展示在信纸里；没有“收下”也已经完成结算。收下后回房间，首次收藏可引导纪念册。

### 6.2 完成

#### 现行交付（v1）

- 至少有一笔真实非橡皮笔迹；空白、只有贴纸或只有擦除不算完成。
- **不评分**，不限制绘画质量，不设置最低时长；不接入画面识别或远程 AI 评画。
- v1 **没有**「告诉宠物我想表达什么」步骤；完成流程不依赖文字或语音解释。固定发星与 §7.5.1 轮换短句，不因解释多而多发星。

#### v2 本地完成门槛（已定规则 · **未实现**）

目标：减少乱画灌水；**不**用数字分、**不**声称「画得像」，**不**接入远程 AI。实现另开任务；未上线前验收与 mock 仍按 v1。

须**同时**满足以下三条，方可成功完成「画好了」：

1. 至少 **5** 笔真实非橡皮笔迹；
2. 有效作画时长至少 **15** 秒（暂停、切后台不计）；
3. 将可画区域近似划分为 **100** 个格子，笔画经过的格子至少 **5** 个（约 **5%**）。

**未达标时的 UI（已定）**：

- 画布上**不**常驻进度条、「还差几笔」等面板。
- 「画好了」可点，但**不完成**、不导出、不发完成星、不进入回礼判定；轻提示一句，不报具体缺哪一条、不报数字：  
  **「再画一会儿，让我看得清楚一点。」**
- 达标后与现行一样完成；**不**弹完成度、百分比或分档庆祝。

**废止**：不以 50／70／80 或其它相似度分档作为 v1／v2 规则；决策清单中同类待问删除。

### 6.4 道具简笔挑战（已定规则 · **未实现**）

目标：在「一起画」中让用户**短暂看见**当日道具的**简笔形态**并临摹完成，减少乱画灌水；**不**用相似度打分、**不**接入远程 AI 识图。实现与简笔素材另开任务；未上线前验收与 mock 仍按 §6.2 现行 v1（及无道具简笔流程）。

#### 触发范围

- 仅当今日信件信内核心为**一起画**，用户从信内进入「一起画」，且该次陪伴**绑定一道具主题**（例如拨浪鼓）时启用本挑战。
- 不扩展为任意日、任意入口的常驻玩法；其它第二期道具与活动解锁仍见 §2 范围表。

#### 闭环（与 §6.1 叠加，不替换回信纸主链）

1. 画布成功就绪 → 按 §6.1 发当日尚未领取的基础奖励（若有）。
2. **看一看**：道具**线框简笔**（与纪念册道具同款线框形态，非照片）叠在蛋形画布中央；同时显示 **「还有 X 次机会看一看」**，**X = 还剩几次能再看简笔**（**不是**还差几次达标才能拿道具）。
3. **约 5 秒**后简笔以 **flip** 动效自动消失；**消失后**用户才开始在蛋形画布上作画。简笔展示期间**不接收笔迹**。
4. 同一道具挑战内共有 **3** 次「看一看」；**每完整展示并 flip 收起一次**消耗 1 次，**X 递减**（例如第 1 次结束后 X=2）。画布就绪后**首次自动**第 1 次看一看；**X>0** 时用户可点 **「再看一眼」** 再展示一次（仍约 5 秒 flip）。**X=0** 后不再展示简笔，仍可作画并点「画好了」。
5. 用户创作 → 点「画好了」→ 须**同时**满足 §6.2 **v2 本地完成门槛**（≥5 笔非橡皮 · ≥15 秒有效作画 · 约 100 格中 ≥5 格）；未达标：不完成、不导出、不发完成星、不进入 §7.5.1 回礼判定，仅 §6.2 轻提示，**不**报还差几笔／几秒；用户可继续画并再次点「画好了」，**无**「必须再成功 N 次才给道具」的计数。
6. **任意一次**达标并成功导出 → 进入 §6.1 **回信纸**主链：展示**本次**作品、宠物回应，以及绑定道具的**真实形态**（非线框、非相似度评分）与 **「收下」**。**不**要求在导出前或导出后再累计多次达标；一次画好即进入步骤 7–8。
7. **星星**仍只走 §5.2 与 §7.5.1，**不另开经济线、不扣星**：同一自然日内「画画额外」基数与 §7.5.1 小回礼**各最多一次**（落在**该次**达标导出／回信纸结算）；进入画布时已领取的「开始基础」不因重复点「画好了」重复发放。道具入册**不**占用 §5.2 两份基数额度。
8. 用户在回信纸点 **「收下」** → 道具**保存**至纪念册 **「回忆」**中的 **道具**条目（与照片、用户作品并列；不进「活动」兑换 Tab）→ 按 §6.1 回到房间。**不**强制用户在同一次挑战内再开第二轮、第三轮作画；若未达标则仍停留在画板，直至达标或用户退出。

#### UI（已定）

- **看一看进行中**：线框简笔在蛋形画布上；顶栏下（或画布上方）显示「还有 X 次机会看一看」（含数字 X）；**约 5 秒**后 **flip** 消失；此阶段**不**接收笔迹。
- **看一看结束后**：蛋形画布恢复为空（保留用户已画内容）；**X>0** 时显示 **「再看一眼」**（仅此一处触发再看，不另开预览窗）；用户正常用画笔／橡皮／贴纸／撤销／清空。
- 画布上**不**常驻笔数／时长／格子进度条；**不**显示「还差几次达标拿道具」或 v2 百分比；**不**在画板区以道具真实形态作为「第 N 次导出」的解锁演出。
- **回信纸（步骤 6 导出成功后）**：作品区旁展示道具**真实形态**（如拨浪鼓，**不**加方形卡片或底板）与 **「收下」**；收下后提示已入纪念册「回忆·道具」（具体文案与动效待 COO 定稿）；**不**弹完成度分档或 AI 评分庆祝（与 §6.2 一致）。星动效仍按 §5.3 在信纸上方展示，不新开奖励窗。

#### 状态与边界

- 看一看次数与「是否已在回信纸收下道具」绑定**当次道具挑战**（自该信内进入一起画起）。本次小程序运行期间尽量保留进度；**不**承诺关闭小程序或跨设备后的恢复（与 §6.3、§9 交付限制一致）。
- 退出、导出失败、跨日草稿等通用规则仍适用 §6.3；道具挑战中途退出：已消耗看一看次数与草稿按实现约定保留或冻结，**不**因退出追回已发开始星；**未**导出成功前**不**展示回信纸道具与收下。

**废止**：不以「看满 3 次看一看即送道具」代替 v2 达标导出；不以**累计 3 次**达标导出作为入册前置；不以 50／70／80 相似度或远程 AI 判定「画得像不像」。

### 6.5 废止：主题画画（60/30/10 档位草案）

### 6.3 退出、失败与跨日

- 进入后退出：开始奖励保留，不追回；不发完成奖励；「一起 X 天」仍只由开信纸决定（见 §5.1.1）。
- 本次小程序运行期间保留草稿，返回继续不重复发开始奖励；不提供关闭小程序后的草稿恢复承诺。
- 导出失败：保留作品，不发完成奖励，允许重试；不因失败改动天数。
- 导出进行中返回：等待当前保存结果，避免丢失或重复提交。页面销毁后的迟到回调不能发奖或清空草稿。
- 返回信纸导航失败：允许重试导航，不能再次发奖。
- 跨日恢复昨日草稿：不因恢复自动发今天的基础奖励；今天成功完成可得今天的画画额外奖励（「一起 X 天」见 §5.2 开信纸）。随后主动开始新作品，仍可领取今天未领取的基础奖励。
- 同一作品重复提交不重复结算；已完成作品与回应在本次运行中保留，重开可收藏。

## 8. 关系与输入原则

每次陪伴有一个明确核心动作；选择、文字、语音帮助理解用户意图，不要求每天说话。当天意图影响当天节奏，长期喜好影响后续内容；“今天不想画画”不能直接变成“不喜欢画画”。

用户明确表达的长期喜好可进入记忆目标；推测喜好先轻量确认，用户可纠正或要求忘记。不新增喜好列表设置界面。真实存储、删除和模型安全能力由 CTO 实现与确认，当前本地模拟不能视为已经具备。

关系变丰富体现在引用共同经历、内容贴合喜好、选择改变后续事件；第一期目标是做出可验收的小链路，而非仅改变称呼。随关系解锁新活动保留为后续方向。

## 9. 数据与实现交接

当前前端结算和活动为本地模拟。除读信提示等界面状态外，不能承诺星星、免费资格、草稿、作品在小程序重启或跨设备后仍保存。当前仅交付前端静态 UI；未来若接入正式服务，再由 CTO 对接账户化，不扩展本次开发范围。

| 业务状态 | 必须表达的含义 |
|---|---|
| dateKey | 北京时间自然日 |
| balance / companionDays | 可用星星 / **连续**有效陪伴日数（**断开清零**），分别记录 |
| dailyBasis | 当日冻结基数 |
| baseClaimed / drawingBonusClaimed | 当日基础与画画额外奖励是否已结算 |
| effectiveDone | 当天是否已记有效陪伴 |
| draft / completedDrawingIds | 本次运行草稿与已完成作品的去重标识 |
| activity.current | 当前茶会选择、确认或结果状态 |
| activity.firstResultSeen | 首次茶会结果已收下，允许后续付费 |
| collectedMemories | 照片或作品 ID、图片、标题、回应、日期 |

业务动作需保持“读取今日状态、领取基础奖励、完成画画、确认茶会、收藏回忆”各自清晰；字段是现有前端交接概念，不是已部署服务端 API。服务端应统一处理日界、重试、并发、余额及去重，不能让模型决定经济结算。接入前不使用真实个人信息做模拟样本。

## 10. 验收清单

### 入口与信件

1. 左上仅余额和一起天数；右下设置保留，百宝箱首项为纪念册。
2. 当天首次进入，动画只在左下圆内约一秒；没有跨房间飞行，不自动开信。
3. 系统静音时无到信声音；声音失败仍可打开信。当天再次进入不重播。
4. 实际打开信后红点消失，未完成动作也可关闭。
5. 信纸没有陪伴/聊天分栏和聊天文字按钮。
6. 在家点击明天：线索展开，正确宠物约一秒上移淡入后停住；动画中点击可进入聊天。
7. 外出点击明天：只有线索，无聊天角色；不能借此绕过聊天限制。
8. 关闭重开、聊天返回保留展开状态；次日重置提示，不清空账户目标数据。

### 奖励与画画

9. 阅读、点明天和收藏均不发奖励或增加天数。
10. 前两天基数 10；第 3、7、14、21、30、45、60、90 个有效日分别变为 11、12、13、14、15、16、17、18；边界前一天仍为前档。
11. 当日第一次结算后基数冻结；已有两天时开始与完成各 11 星，完成前天数不增加。
12. 打开失败或画布未就绪不发开始奖励；成功就绪仅发当天尚未领取的基础奖励。
13. 先普通完成再画画，开始不再发基础奖励，首次画好仍发额外奖励；天数仍只增加一次。
14. 空白、贴纸或纯擦除不能完成；真实笔迹成功导出后额外奖励与有效日各只结算一次。
15. 中途退出保留开始奖励和本次运行草稿，不发完成奖励；再进入不重复发开始奖励。
16. 导出失败可重试；导出中返回、页面销毁回调、导航重试不造成重复奖励或丢稿。
17. 跨日恢复旧草稿不自动发新日基础奖励；新日完成按新日规则结算。
18. 作品与回应在信纸展示；不点收下也已发奖，重复收下不重复入册。
19. 孵化前画画流程保持原行为；陪伴作品不覆盖蛋壳。
20. 系统减少动态效果时仍能看到准确数值；信纸内装饰光点不被当成奖励数量。

**道具简笔挑战（规则验收 · 未实现，见 §6.4）**

21a. 绑定道具主题的一起画：线框简笔叠在蛋形画布；显示「还有 X 次机会看一看」（X=剩余可看次数）；约 5 秒 flip 消失；看一看期间不接收笔迹。
21b. 共 3 次看一看；X>0 时可「再看一眼」；X=0 后不再展示简笔，仍可作画。
21c. 未达 §6.2 v2 三门时不导出、仅 §6.2 轻提示；**一次**达标并成功导出走 §6.1 回信纸（作品 + 宠物 + 道具真实形态 +「收下」）；§5.2 画画额外与 §7.5.1 小回礼同一自然日各最多一次（§6.4 第 7 步）；**不**要求同次挑战内再画第二、第三轮才给道具。
21d. 用户在回信纸点「收下」后，道具保存至纪念册「回忆」中的道具条目；不扣星兑换；**不**在画板区以「第 3 次导出」才展现道具。
21e. v2 与 §6.4 未上线前，不以 mock 默认具备简笔 flip 或道具入册能力。
21f. **不得**交付废止的主题画画：无 60/30/10 档位、无方形主题参考画布、无「一起画完啦！」/「有份小礼物！」/「惊喜加倍！」档位庆祝标题（§6.5）。

### 茶会与纪念册

21. 首次茶会免费；清茶/花茶选择后给对应回应，但必须再点确认才完成。
22. 开始与退出不扣星；确认完成才扣 20 星或使用免费资格，照片失败不结算。
23. 未收下结果时再次进入恢复原结果，不生成第二次免费活动；收下后下一次显示 20 星。
24. 重复点击确认和收下不重复扣费或入册；余额不足保持可返回状态。
25. 外出不能新开始茶会；已有进度和结果可恢复。
26. 玉兔、锦鲤都用自身窗边照片；回忆与活动两个入口简短且清晰。

### 交付限制

28. 不把本地模拟当真实持久账户，不把上述自动检查当手机视觉、声音、震动和真实画布验收。
