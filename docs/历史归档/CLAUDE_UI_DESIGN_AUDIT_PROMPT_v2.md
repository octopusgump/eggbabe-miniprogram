## 2 · 复审方法

1. 完整阅读 `docs/eggbabe-DESIGN.md`，作为本次检查标准。
2. 阅读 `git diff d91c0b1..cd10d0c`，理解本轮实现。不要只依赖提交说明或自动测试。
3. 审查对象包含当前分支已提交代码**与工作区未提交内容**，两者分开报告。保留工作区现有内容，不清理、不覆盖、不纳入提交。
4. 如能运行微信开发者工具，覆盖常见手机尺寸与窄长屏；不能运行时，明确标注哪些结论仅来自静态检查。
5. 每条结论必须引用文件路径与行号。无法由代码直接证明的，归入「无法静态验证」清单，不写进问题表。

## 3 · 严重度定义

| 级别 | 判据 |
| --- | --- |
| Blocker | 违反 design.md 明文硬规则，且用户可见；或显示错误素材、错误角色、错误天气；或出现被禁止的任务化 / 催回访表达；或候选与开发资源进入正式包。 |
| Major | 违反 design.md 规则但触发路径较窄；或缺失必需的失败 / 重试 / 可返回状态；或无障碍语义缺失。 |
| Minor | 数值偏差（色值、字号、时长、尺寸）不影响功能语义。 |
| Info | 文档与实现口径不一致，需修文档而非改代码。 |

## 4 · 必查项目

### A · 素材门禁与回退（design.md §1.3、§4.3、§5）

1. 破壳前 36 个环境键的映射声明是否完整、路径唯一、且只指向正式运行时目录。**不要求 36 套素材齐备**，要求缺图时落到显式错误态。
2. 房间、蛋体或窝垫加载失败时，是否显示持久错误、重试与安全返回，而不是拼 CSS 房间。
3. 是否存在任何跨天气、跨季节、跨时段、跨角色、跨目的地的素材复用兜底（含 `||` 默认值、try/catch 内静默降级、配置层 fallback 字段）。
4. 破壳后动作是否只使用已烘焙角色、道具、接触阴影与环境光的完整全景；运行时不得叠加透明角色、CSS 道具或色调层。
5. 找不到动作全景时，是否回到**同环境**空房全景。
6. 玉兔夜间关灯版本是否只在玉兔生效；锦鲤缺资产时是否明确不复用玉兔。
7. 特殊天气版本是否只使用已登记的四种（玉兔春阴玉兔秋雨日落看书、锦鲤夏暴雨夜睡觉、锦鲤冬雪看窗外）。
8. 资产尺寸门禁：破壳前中央场景 `941×1672`、破壳后全景与动作全景 `2823×1672` 不透明、明信片 `1600×900` 16:9 不透明。是否有校验脚本或 CI 拦截。
9. `_candidates/`、参考合成图、实验目录、`egg-rotation-sample` 等开发资源是否全部排除在 trial／release 包外，且未在 `app.json` 注册。动作全景与大图是否走 `environment_cdn_base`、不进主包。
10. 页面代码是否存在自行拼接资源路径的行为（只允许读配置文件登记项）。

### B · 破壳前首页与三段操作组（§4.1）

11. 首页是否为全屏孵化房间，不是卡片式仪表盘。
12. 季节、天气、日间状态是否由稳定规则决定；正式版是否已移除手动场景切换。
13. 许愿／早教／画蛋壳是否为一个三段胶囊操作组，每段 `112rpx`。
14. 锁定态是否使用灰阶图标与遮罩，**不得**通过整体降透明度实现。
15. 首次命名与后续改名是否都留在当前场景的底部面板，并适配底部安全区。

### C · 破壳后生活空间与状态（§4.2）

16. 是否使用单张三屏连续全景，进入时直接定位到 ta 所在屏，不从错误屏播放滑入动画。
17. 场景切换是否先预加载、成功后交叉淡化；失败时是否**保留旧场景**并给出重试（不得白屏或回到默认屏）。
18. 大状态是否只有家、旅行、打工、上学四种。
19. ta 外出时是否显示空着的家 + 第一人称去向文字；是否有目的地图片被放进实时生活空间。
20. 每个居家小状态是否只有一个固定对应动作，且动作使用场景内已有物件、不新增「互动」按钮、无提示与预告。
21. 八个居家状态是否都显示对话入口，并直接进入完整对话页；外出时左下角是否**什么都不显示**，且不得出现对话、写信、留言、回信入口或相关弹层。
22. 右下角是否只显示“我的／设置”齿轮入口并直接进入“我的”；是否完全没有百宝箱弹层、复杂内容入口或相关未读红点。

### D · 蛋壳绘画（§4.4，本轮遗漏最多的一节）

23. 画布是否占页面主要面积（约 `89vw`），底部工具条与右侧撤销／清空是否遮挡主绘制区。
24. 双指缩放下，绘制坐标是否做了反向映射，笔迹是否不漂移。
25. 是否为五种颜色、五档粗细、默认 `5px`；每一笔是否保存自己的颜色（不得整幅统一取当前色）。
26. 橡皮擦是否可连续擦除笔迹与贴纸；撤销、清空、「撤销清空」是否共用同一历史状态。
27. 停止绘制约 `700ms` 后是否自动保存；导航栏是否持续显示保存中／已保存／未保存。
28. 撤销与清空的禁用态是否使用专用置灰图，而非降低按钮或标签整体透明度。

### E · 回忆、纪念物、明信片、收藏卡（§4.5）

本节除第 29 条发布门禁外，只检查 develop 环境中保留实现的质量，不得据此要求 trial / release 恢复入口。

29. V3.6 / V3.7 的 trial / release 是否无法从生活空间、“我的”页、旧路径或分享路径进入纪念物、明信片、收藏卡和旅途回放；develop 是否仍可验收保留实现。
30. 纪念物是否只显示真实出现的物件、三列缩略图；是否出现锁定格、总数、稀有度或完成度。
31. 纪念物详情是否以单件主图为首屏焦点，下方为桃粉色第一人称「我还记得」区。
32. 明信片列表是否只显示封面、标题、日期；同一次旅行是否按 `journey_id` 聚合为一个入口。
33. 全屏旅途回放是否只浏览历史图片、不改变 ta 当前状态；是否出现假的滑动胶囊、`1/N` 进度或收集提示；加载与错误状态是否始终可返回。
34. 今日收藏卡是否只推荐一张真实收藏卡。
35. 纪念物、明信片、旅途图、收藏卡是否都有加载、失败、**单项重试**与可返回状态。

### F · 视觉基础（§3）

36. 全量扫描代码中的 hex 与 rgb 色值，逐一比对 design.md §3.1 色表，列出所有表外色值。重点核：主交互 `#002900`、按下 `#001A00`、一级 `#1A1A1A`、二级 `#5C5C5C`、三级 `#8C8C88`、页面底 `#FAFAF8`、卡片 `#FFFFFF`、分隔线 `#E5E3DF`、品牌绿黄粉 `#9DB65B`／`#EDE78E`／`#F4B9AE`、回忆 `#FFF6F5`／`#80625D`、错误 `#D9463C`／`#FDECEA`。
37. 字体栈是否统一为 `PingFang SC, Helvetica Neue, Microsoft YaHei, sans-serif`。
38. 字重是否不超过 `600`，是否存在 `700` 或伪粗体。
39. 用户可见辅助文字是否不小于 `20rpx`，正文是否在 `24–30rpx`。
40. 单个紧凑控件是否为 `112rpx × 112rpx` 圆形；成组控件是否为每段 `112rpx` 的统一胶囊；文字主按钮是否为 `96rpx` 高胶囊；紧凑按钮是否误用中圆角矩形。
41. 常规按压是否统一为 `160–180ms`、`scale(.98)`；回忆卡高光是否不超过 `400ms`。

### G · 信息层与文案红线（§1.4、§6）

42. 场景图内是否烘焙了标题、日期、正文、按钮或状态；明信片图是否含文字、Logo、UI 或水印。
43. 是否出现倒计时、完成率、剩余次数常驻角标、或诱导回访文案。特别核 `slot_end` 是否被用于任何用户可见的倒计时或预告（结构说明明确红线）。
44. 系统开启「减少动态效果」时，位移、旋转、循环动画是否正确停用，静态状态反馈是否保留。
45. 图形按钮、蛋体、工具入口、导航、协议勾选是否具备准确的 `aria-role`／`aria-label`／状态语义；纯装饰层是否不进语义树。
46. 顶部导航、底部操作、全屏回放是否适配横竖屏安全区。
47. 开发验收器是否只在 `localDemoEnabled` 下显示，不进 trial／release，且不修改 live 数据。

### H · 跨文档冲突必查

48. **动作集合对齐。** design.md §4.3 列出睡觉／看书／打游戏／看窗外／画画／听音乐；《日常陪伴系统结构说明 v0.3》§4.2.1 列出睡觉／赖床／发呆／涂涂画画／打游戏／看窗外，并绑定唯一对应动作与「能否说话」。请以运行时配置为准，输出实际实现的完整状态表，标出两份文档各自缺失的条目，并给出建议的单一化口径。
49. **窗洞透明是否仍成立。** 结构说明 §11 要求破壳前房间背景 PNG 的窗洞留透明，窗外走 7 底图 + 3 叠加层。若 36 个环境键已是预合成整图，说明分层天气系统已被替换。请核实实现，并把结论标为架构级变更（Info 或以上），不要只当素材问题处理。

- 代码／UI 是否正确拒绝错误素材并提供错误与重试状态；
- 正式美术素材是否齐全。

不要建议恢复跨天气复用来掩盖缺图。
