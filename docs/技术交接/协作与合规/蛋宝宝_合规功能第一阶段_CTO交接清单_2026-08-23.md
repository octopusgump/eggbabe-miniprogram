# 蛋宝宝合规功能第一阶段 CTO 交接清单

> 前端基线：当前工作分支 `wip/post-hatch-uncommitted-20260814`（以最终交付 commit 为准）
> 当前状态：前端 UI、状态和接口适配已完成；正式服务端联调与法务终审未完成。

## 一、CTO 本次要交付什么

| 接口 | 必须完成的服务端行为 |
|---|---|
| `getAgeRange` | 按当前登录账号返回年龄区间；空值或未知枚举按未设置处理 |
| `saveAgeRange` | 校验枚举并保存到账号，换设备登录仍可读取；成功时回传最终保存值 |
| `submitFeedback` | 保存反馈并返回唯一受理编号；按 `request_id` 幂等 |
| `getComplianceConfig` | 返回 12356、110、120，以及用户服务协议和隐私政策元数据 |
| `requestChatHistoryExport` | 按当前账号汇总全部对话并发送到用户填写的邮箱；返回唯一 `export_request_id` |
| `deleteAllChatHistory` | 删除当前账号下全部蛋宝宝的聊天记录；完成后返回 `deleted: true` 和删除凭据 |

统一成功响应需包含 `success: true`、`data.mode: "live"`、`request_id` 和服务端时间；失败响应需提供稳定 `error.code` 与可展示的中文 `error.message`。

## 二、项目边界

本次只完成上述六个接口及联调，不新建手机号、短信验证码、完整生日、身份证、监护人验证、监护人后台、分龄保护模式、语音功能、危机系统或反馈工单查询页。

当前 300 条消息提醒由前端按单次会话计数，不新增服务端计数接口，也不能把 300 条写成“三小时”。已有真实连续使用时长机制继续独立维护。

## 三、固定数据合同

年龄区间只有四个合法值：

| 页面选项 | 保存值 |
|---|---|
| 14 周岁及以下 | `AGE_0_14` |
| 15-35 周岁 | `AGE_15_35` |
| 36-60 周岁 | `AGE_36_60` |
| 60 周岁以上 | `AGE_61_PLUS` |

60 周岁属于 `AGE_36_60`，`AGE_61_PLUS` 从 61 周岁开始。服务端只保存区间，不反推具体年龄，也不自动映射保护模式。

反馈请求字段固定为：

```json
{
  "type": "AI_CONTENT_VIOLATION",
  "description": "用户填写的问题描述",
  "consent": true,
  "message_id": "可为空",
  "submitted_at": "客户端提交时间"
}
```

成功响应必须包含非空 `receipt_number`。有 `message_id` 时，服务端必须验证该消息属于当前账号可访问的对话。

## 四、当前口径覆盖旧 PRD

以下是已经确认的当前版本，CTO 不要根据旧 PRD 自行恢复：

- 协议区只保留“用户服务协议”和“隐私政策”，不返回或展示独立儿童政策；
- 当前聊天页不提供长按复制、长按举报、退出对话或聊天内清空入口；账号级导出和删除统一放在“我的 → 对话记录”；
- 当前健康提醒只保留“我知道了”；
- 帮助中心使用客服邮箱，不展示客服电话和服务时间；
- 旧“账号”页、退出登录、清除本地数据、注销账号及 `manageDeletion` 已从当前线上范围完全删除，不得恢复。

如需恢复上述能力，先由产品重新确认，再同步修改前端和自动化测试。

## 五、CTO 需要特别注意

1. 年龄值必须绑定经过认证的账号，不能信任客户端传入的用户身份；
2. `selected_at` 和 `submitted_at` 只是客户端时间，数据库同时记录服务端时间；
3. `saveAgeRange` 和 `submitFeedback` 均按 `request_id` 幂等，网络重发不能重复写入或生成两个工单；
4. 未知年龄枚举不能静默纠正，返回失败或未设置，让用户重新选择；
5. 反馈描述和聊天正文不得完整写入普通应用日志；后台访问权限和保留期限需与法务确认；
6. 合规配置只允许 `service`、`privacy` 两类政策，正式链接必须使用 HTTPS 业务域名；
7. 12356、110、120 是现实求助号码，配置失败时不能被其他营销或客服号码替代；
8. 前端通过不等于服务端合规完成，上线前必须做 trial 真机联调。
9. `requestChatHistoryExport` 必须校验邮箱格式、当前账号身份并按 `request_id` 幂等，邮件内容和下载链接需限时、鉴权且避免跨账号访问；
10. `deleteAllChatHistory` 必须由服务端真实删除账号级全部对话，不能只返回“已受理”；仅在删除完成后返回 `deleted: true`，并生成可审计的删除凭据；
11. 删除接口不得信任客户端传入用户 ID，也不得把系统审计最小留存误当作仍可恢复的聊天记录。

## 六、联合验收

- [ ] 新账号没有年龄值时不能进入 AI 对话；
- [ ] 四个年龄值保存后，重新登录和换设备均能正确读回；
- [ ] 空值或未知年龄枚举会重新触发选择；
- [ ] 设置页修改失败时数据库旧值不变；
- [ ] 同一反馈请求重复发送只生成一个受理编号；
- [ ] 非当前账号的 `message_id` 无法关联；
- [ ] 合规配置只返回两份政策及正确求助号码；
- [ ] 接口超时、断网和业务失败均返回稳定错误，不出现假成功。
- [ ] 导出覆盖当前账号下全部蛋宝宝的对话，邮件只发送给本次填写且校验通过的地址；
- [ ] 相同导出请求重复发送只生成一个 `export_request_id`；
- [ ] 删除完成前不返回 `deleted: true`，完成后所有设备均无法再读取已删除对话；
- [ ] 非当前账号无法导出或删除其他账号的对话记录。

## 七、上线前确认

用户服务协议、隐私政策的正式正文、版本号、生效日期、备案域名、数据保留期限和后台访问范围，仍需法务确认。第一阶段 MVP 不应表述为已经满足全部合规要求。
