## 一、直接采用的八条

### 1. 第一天定清四个边界

- 产品载体：普通小程序、小游戏或纯视觉原型；
- 前端边界：页面、交互、状态、fixture 和 adapter；
- 服务端边界：正式数据、幂等、鉴权、数据库、广告校验和监控；
- 视觉边界：设计稿、Token、资产目录和禁止自行发挥的部分。

载体没有确认时仍可做不依赖平台的静态体验，但不能把原型称为正式小游戏能力。

### 2. PRD 先写“不做什么”

每份功能 PRD 第二节固定写项目边界，并点名服务端部分归 CTO。只写“不做后端”不够，要列出数据库、正式鉴权、幂等、远程 AI、广告校验和数据入库。

### 3. 数据合同早于页面接线

页面只消费统一视图模型。静态 fixture、adapter 和真实接口保持同形状，服务端接入时只替换数据源，不把业务字段散落在页面里。

### 4. 静态演示必须诚实

- fixture 固定标记 `source: local-fixture`；
- 失败状态不回退到“看起来成功”的假数据；
- 未配置接口不算前端缺陷，但页面必须有加载、空态、失败和重试；
- 前端不能显示“已同步、已删除、已校验、已发奖”等服务端没有确认的事实。

### 5. 人工介入只留三处

- 开工前：CEO / 产品负责人拍板载体与范围；
- 联调时：CTO 提供真实样例、环境和接口行为；
- 合并前：所有者看成品和范围差异。

其他能由前端自动验证的内容，不拆成操作清单交给用户。

### 6. 一个分支交付一件完整的事

“一件事”可以包含页面、必要组件、fixture、测试和交接说明，不必为了文件类型拆成多个分支；但不要把无关资产清理或另一套功能顺手塞进来。

### 7. 验收必须看真实视口和状态

- 至少覆盖小屏手机和常用大屏；
- 固定定位元素使用限定视口截图，不用整页截图判断位置；
- 每个加载、空、错、重试、长文案和不可用状态都能单独切换；
- 有 Figma 定稿时按定稿实现，并列出所有主动偏差。

### 8. 没复现过的原因不写进 PRD

结论区分“实跑确认”和“读码推断”。推断可以作为排查线索，不能作为产品事实。用户看到的真实现象与推断冲突时，以真实现象为准并撤回旧结论。

## 二、适合拆分的工作包

| 工作包 | 主要产物 | 是否依赖 CTO |
| --- | --- | --- |
| A. 今日陪伴 UI | 首页、宠物状态、对白、轻互动 | 不依赖，使用 fixture |
| B. 星星与解锁 UI | 进度、首次得星、重复领取、解锁状态 | 不依赖，正式幂等由 CTO |
| C. Tomorrow Engine UI | 普通、惊喜、外出、归来和次日延续状态 | 不依赖，正式调度由 CTO |
| D. Reward Reveal | 通用动效、声音 / 触觉开关、Rare 保存入口 | 不依赖 |
| E. 纪念册 | 列表、锁定轮廓、详情、保存卡 | 不依赖 |
| F. 广告状态 UI | 可用、加载、完成、取消、失败、不可用 | 不依赖，真实广告由 CTO / 平台 |
| G. 合规静态页面 | 协议入口、AI 身份提示、健康使用提示 | 不依赖，最终文案需法务 |
| H. 接口合同 | adapter、fixture、枚举、错误态和合同测试 | 前端先出，CTO 评审 |
| I. 正式服务 | 数据库、鉴权、幂等、防刷、广告校验、入库 | 完全交给 CTO |

A–H 可以在不等待正式服务端的情况下推进。每个工作包都必须带状态截图、fixture 和验收结果，不能只交一个“正常状态”页面。

## 三、不迁移的内容

以下经验属于“标看看”的服务端、爬虫或部署场景，本前端静态项目不照搬：

- ECS、nginx、systemd、定时抓取、数据快照和发布回滚；
- 爬虫来源核验、公告样本、抓取成功率和境内网络；
- 服务端鉴权参数、数据库迁移和生产监控；
- 为多 Agent 高并发开发建立过重的审核窗口和复杂 PR 流程。

这些工作若未来出现，应由 CTO 的服务端仓库建立自己的规则。本仓库只保存接口合同和前端联调事实。

## 四、每个前端任务的完成定义

1. 正常、加载、空、失败、重试和不可用状态均可演示；
2. fixture 与 adapter 字段一致；
3. 页面不直接实现服务端业务真相；
4. 自动化测试和项目校验通过；
5. 真实未验证项单独列出，不与已验证结果混写；
6. 分支、提交和交付去向明确，不留下只存在于本地的孤本。
