## 一、这是什么

这是一个用于验证“每天回来陪它一会儿”的前端静态体验：用户看到宠物今天在做什么，完成一次轻互动，看到星星和一段纪念内容，并在离开前得到一个明天再回来的理由。

| 容易混淆的概念 | 本项目里的含义 |
| --- | --- |
| 前端静态验收版 | 页面、动效、状态切换、固定模拟数据和接口适配器；可以完整演示，不代表真实业务已运行 |
| 正式 IAA 产品 | 真实账号、服务端幂等、跨设备数据、广告结算、内容下发和埋点入库；由 CTO 后续实现 |
| 星星 | 陪伴记录的视觉表达，只用于解锁纪念内容，不充值、不交易、不提现 |
| 明日钩子 | 一句或一个场景上的未完成事件，不是签到奖励、倒计时或断签惩罚 |

## 二、项目边界

**本项目只做前端静态 UI、交互和视觉验收。** 所有业务数据来自明确标记的本地 fixture，通过可替换的 adapter 读取。

本项目内完成：

- 今日陪伴首页及普通、惊喜、外出、归来四类演示状态；
- 轻互动、当日首次得星、重复互动、纪念解锁的完整视觉流程；
- Reward Reveal 动效、纪念册、纪念详情和“保存这一刻”静态分享卡；
- 激励广告的加载、可看、完成、取消、失败、不可用状态演示；
- 加载、空态、失败、重试和开发态状态切换器；
- 前端 adapter、字段合同、模拟响应和自动化测试。

以下不在本项目实现，统一交给 CTO：

- 云函数、数据库、正式鉴权、跨设备同步、服务端时间；
- 每日得星幂等、防刷、补偿、数据迁移和审计记录；
- Tomorrow Engine 的正式概率、内容调度、用户分群和远程配置；
- 广告位创建、真实广告 SDK、服务端奖励校验、结算和反作弊；
- 正式埋点接收、数据仓库、留存计算和运营后台；
- 大模型、语音、内容安全审核和远程内容生成。

**本地 fixture 只能证明界面可用，不能被表述为“星星系统、广告系统或留存系统已经上线”。**

微信普通小程序与微信小游戏的载体选择由 CEO 另行确认；确认前，本项目只验证不依赖载体的用户流程和视觉反馈，不做平台迁移。

## 三、成品长这样

```text
打开
  ↓
今天：玉兔在窗边画画
“我还没画完，明天再给你看。”
  ↓
用户轻触 / 陪它坐一会儿
  ↓
今日首次陪伴  +1 星
  ↓
新纪念达到解锁条件
发现 → 停顿 → 揭晓 → 收下
  ↓
纪念册显示新内容
  ↓
离开前仍能看到一句明日提示
```

首页不出现任务列表、连续签到、断签天数、资源损失提示或强制广告。

## 四、页面和组件

| 编号 | 页面 / 组件 | 前端静态交付 |
| --- | --- | --- |
| F01 | 今日陪伴首页 | 今日场景、宠物状态、对白、轻互动入口、星星进度、明日提示 |
| F02 | Reward Reveal | Daily / Special / Rare 三档演示；Memory 使用完整场景结尾，不套开箱 UI |
| F03 | 纪念册 | 按时间展示已解锁内容；未发现内容只显示柔和轮廓 |
| F04 | 纪念详情 | 图片、日期、地点、角色和一句回忆；Rare / Memory 可进入保存卡 |
| F05 | 保存这一刻 | 场景图、日期、对白和小型品牌标识；不放拉新奖励和大二维码 |
| F06 | 激励广告状态层 | 用户主动触发；完成、取消、失败、不可用均有独立反馈 |
| D01 | 开发态状态切换器 | 切换日期类型、宠物状态、星星数、解锁状态和广告结果；正式界面不显示 |

## 五、必须覆盖的状态

### 今日内容

| 状态 | 页面表现 | 演示占比只用于内容审查 |
| --- | --- | ---: |
| NORMAL | 睡觉、发呆、看窗外等安静状态 | 70% |
| SURPRISE | 新对白、小礼物或特殊动作 | 20% |
| RARE | 外出、访客或特殊天气 | 9% |
| SUPER_RARE | 第一次下雪等完整纪念场景 | 1% |

70/20/9/1 仅作为原 PRD 的内容结构样例。前端不实现随机算法，也不据此伪装正式分发结果。

### 陪伴与星星

| 状态 | 页面表现 |
| --- | --- |
| AVAILABLE | 今天尚未领取，完成有效互动后演示 `+1` |
| CLAIMED | 今天已经领取，重复互动只给陪伴反馈，不重复加星 |
| UNLOCKED | 达到门槛后播放 Reveal，并把纪念内容加入纪念册 |
| ERROR | 保留用户当前画面，提示“刚才没有记下来”，提供重试；不显示假成功 |

### 激励广告

| 状态 | 页面表现 |
| --- | --- |
| AVAILABLE | 用户主动选择“看一段内容，解锁额外纪念” |
| LOADING | 按钮锁定并显示加载状态 |
| COMPLETED | 进入额外内容 Reveal；前端演示数据明确标记为 mock |
| CANCELLED | 返回原场景，不发放奖励，不责备用户 |
| ERROR | 显示“现在暂时看不了”，可关闭或重试 |
| UNAVAILABLE | 隐藏入口或显示不可用说明，不阻断基础陪伴 |

## 七、关键交互规则

1. 每日首次有效陪伴演示 `+1 星`；重复互动不重复加星。正式判定由 CTO 服务端返回，前端不根据本机日期自行认定成功。
2. 用户几天没来不扣星、不清零，也不显示断签天数。
3. 宠物外出时可以看到纸条或环境变化，但不弹“任务完成”。
4. Reward Reveal 默认 2.2 秒，范围 1.5–3 秒；必须包含至少 0.2 秒的明确停顿。
5. 一次 Reveal 最多一次主视觉重点、四层声音和三次触觉；静音、关闭震动时体验仍完整。
6. 激励广告只能由用户主动触发；取消和失败不发奖励，也不阻断当天的基础陪伴。
7. 所有失败状态诚实显示失败，不回退到另一份“看起来成功”的演示数据。

## 九、数量

- 5 个用户可见页面 / 状态层：今日首页、纪念册、纪念详情、保存卡、广告状态层；
- 1 个通用 Reward Reveal 组件；
- 1 个仅开发态可见的状态切换器；
- 4 类今日内容状态；
- 4 类陪伴 / 星星状态；
- 6 类广告状态；
- 首批 3 条候选纪念内容。

这里的“状态”不是新增页面，不能把数字相加后当作页面数量。

## 十、前端验收

1. 开发态可以逐一切换四类今日内容、四类星星状态和六类广告状态；
2. 正式构建不显示状态切换器，也不把 `local-fixture` 表述成真实用户数据；
3. 当日首次互动能完整演示 `+1`、进度变化和达到门槛后的 Reveal；
4. 重复互动、广告取消和广告失败均不会演示重复发奖；
5. Reward Reveal 在 1.5–3 秒内结束，至少有 0.2 秒停顿，结束后只回到原场景，不弹第二层“恭喜获得”；
6. 纪念册能正确展示锁定、已解锁和新解锁三种状态；
7. 加载、空态、失败、重试都有独立画面，失败时不显示假成功；
8. 小屏长文案不溢出，交互热区不小于 44px 等效尺寸；
9. 前端代码不新增云函数、数据库、正式账号系统或真实广告奖励逻辑；
10. 所有 adapter 均可被本地 fixture 替换，页面组件不直接读取后端专属字段。
