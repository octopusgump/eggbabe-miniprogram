# 蛋宝宝文档分类与整理计划

整理范围：docs 内 Markdown 业务文档；依赖包自带 README 不作为产品文档。代码、图片、源素材、依赖包和用户 project.config.json 均不清理。

## 分类及执行计划

| 类别 | 保留与整理方式 | 后续计划 |
|---|---|---|
| 当前产品/设计基线 | 主 PRD、Design 保留；新陪伴 PRD 只覆盖本轮模块 | 从索引进入，按模块读取，避免全量旧 PRD 混用 |
| 专项产品与接口 | 聊天、设置、心情、技术、合规分别保留 | 每项按所属负责人和真实交付范围维护 |
| 验收与复核 | 保留独立证据，修正过时状态 | 真机验收后补实际结果，不改写旧检查结论 |
| 陪伴产品规则 | 新 PRD 集中正文，scope 留入口 | 后续机制先写决策清单，定稿再进 PRD |
| 历史产品/实现 | 八份旧文档无损汇编成一个 md | 从工作目录删除重复原文件，Git 历史仍可恢复 |
| 储备、研究、美术和素材 | 保留，明确层级 | 不混入当前功能排期；视觉文件不删除 |

用户本次明确要求执行分类和删除重复文件，优先于旧索引“历史文档不删除”的目录规则；历史内容仍完整保存在汇编中。**可以完全丢弃且没有保留价值的独有文档：本次没有发现。** 删除的是已完整整合的八个重复载体，不是原始决定、接口合同或素材证据。
