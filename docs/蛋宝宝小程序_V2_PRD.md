## 1 · 产品定位

### 1.1 一句话定位

> 一只从实体蛋中诞生、愿意回应你并与你对话的蛋宝宝。

### 1.2 产品形态

蛋宝宝是**实体潮玩 + 微信普通小程序陪伴服务**：

1. 用户在小程序外获得实体蛋和激活码。
2. 在小程序内绑定实体蛋。
3. 用户可自由触摸、装点蛋壳、说话或一起看场景。
4. 到服务端预设时间后，实体装置破壳。
5. 小程序生成一蛋一份的收藏卡，承接实体记忆。
6. 破壳后通过定性状态、生活场景和安全对话持续陪伴。

### 1.3 当前验证目标

- 用户能否顺利绑定和使用实体蛋。
- 自由互动和一对一对话能否提供情绪价值。
- 实体破壳与收藏卡是否具有纪念和分享价值。
- 用户是否在没有任务、奖励或惩罚的情况下自愿回访。

### 1.4 当前产品边界

普通版不提供数值成长与任务、虚拟经济与道具、概率获取与收集解锁、竞技抽奖或资源型商业化。**规范性红线只在[合规与提审清单 C-01–C-10](./蛋宝宝普通小程序_合规与提审清单.md)维护**；本文只保留产品摘要，技术执行见技术规格。

## 2 · 陪伴体验原则

| 原则 | 产品要求 |
|---|---|
| 自由 | 不推每日任务，不显示完成态，用户想来再来 |
| 即时回应 | 每次触摸或说话都有身体、视觉、触觉或文字反馈 |
| 非数值化 | 情绪和关系只用自然语言表达，不建立前台或后台成长值 |
| 一对一 | 蛋宝宝始终用第一人称“我”对用户说话 |
| 不施压 | 不因久未访问表现低落、责备、饥饿或失望 |
| 真实一致 | 产品定位、用户界面、后台逻辑和提审材料保持一致 |
| 弱动效友好 | 系统减少动态效果时降级为静态或淡入反馈 |

## 3 · 用户流程

### 3.1 主流程

**扫码进入 → 微信授权 → 输入激活码 → 绑定实体蛋 → 自由互动 / 装点 / 说话 → 等待服务端生命周期进入破壳阶段 → 实体破壳 → 生成收藏卡 → 查看状态 / 场景 / 对话**

### 3.2 单蛋规则

- 当前普通版一个账号最多绑定 1 只蛋宝宝。
- 已绑定账号再次输入激活码时不新增，也不消耗新激活码。
- 每只蛋只记录服务端生命周期阶段、基础状态、收藏卡和对话记录。
- 不记录由互动累积的孵化进度或关系成长。
- 多蛋持有、切换和联动不进入普通版。

### 3.3 核心状态

| 生命周期状态 | 服务端判定 | 用户界面 |
|---|---|---|
| 未绑定 | 无有效实体蛋绑定 | 空状态 + 添加蛋宝宝 |
| 孵化中 | 未到接近破壳阶段 | 真实蛋体 + 定性文案 + 自由互动 |
| 准备见面 | 接近预设破壳日 | “我准备好啦，就快见面了” |
| 待破壳 | 到达可承接时间 | 查看破壳结果 |
| 已破壳 | 已生成固定结果 | 角色主页、收藏卡、场景、对话 |

界面不显示剩余天数、倒计时、孵化百分比或互动完成进度。

## 4 · 激活码与实体蛋绑定

### 4.1 激活码类型

| 类型 | 用途 | 普通版规则 |
|---|---|---|
| 企业码 | 展会、渠道、合作方 | 可配置使用上限和默认原型 |
| 个人邀请预留码 | 邀请关系追溯 | 不发资源、道具、成长值或抽奖机会 |
| 购买码 | 站外实体蛋交付 | 小程序只核销和绑定，不承接支付 |

**配额与消耗规则**：

- 企业码可一码多用，后台配置使用上限；只有未绑定账号成功绑定后才消耗 1 次额度。
- 个人码在用户绑定第一只实体蛋后自动创建 5 个；每个只能被一个新账号成功使用 1 次，不可自增。
- 个人码只有在受邀账号成功绑定后才标记已使用；不允许自己使用自己的码。
- 购买码与站外订单对应，核销规则不依赖小程序内支付。
- 已绑定账号提交任何新码都不消耗额度。
- 原型可以在绑定后展示，实体款式在破壳承接前保持隐藏。

### 4.2 添加页

- 唯一入口为手动输入激活码。
- 校验由后端完成，前端不得生成或猜测有效码。
- 成功后播放约 1 秒的添加反馈，不提前展示实体款式。
- 文案使用“绑定成功 / 我在这里”，避免“获奖 / 开箱 / 抽到”。

### 4.3 异常状态

至少覆盖：空输入、格式错误、无效码、已使用、已停用、超过使用上限、账号已绑定、网络失败、服务异常、实体原型不匹配。

激活审计至少记录：激活码 ID、类型、使用账号、邀请人 ID（个人码）、来源渠道（企业码）、站外订单号（购买码，可空）、原型、破壳后款式、使用时间和绑定结果。

## 5 · 孵化期首页

### 5.1 首页结构

- 四季昼夜房间背景。
- `egg_base_day.webp` 真实蛋体。
- U 形窝垫接触阴影。
- 第一人称招呼气泡。
- 服务端生命周期的定性状态入口。
- “一起待一会儿”自由陪伴区。
- 常驻说话输入框。
- 底部 Tab：蛋宝宝 / 我的。

右上角不显示露珠余额、孵化圆环或百分比；没有必要信息时允许留空。

### 5.2 真实蛋体硬规则

- 直接保留 `egg_base_day.webp` 的原始高光、青绿色体积渐变、边缘明暗和底部暖阴影。
- 不得重新引入扁平中性白蛋。
- 保留呼吸、轻触压缩 / 回弹、光泽移动和窝垫实时阴影。
- 光泽反馈不得覆盖用户贴纸、图样或手绘。
- 弱动效模式下静止显示，不影响信息读取。

### 5.3 自由陪伴入口

首版保留 8 个无序号、无完成态、无奖励的入口：

1. 摸摸我
2. 跟我说句话
3. 安静陪我一会儿
4. 一起看看窗外
5. 告诉我一个愿望
6. 教我一件小事
7. 画一个小记号
8. 说一句秘密暗号

任何入口都不增加进度、资源或权益。

### 5.4 轻触与长按

- 轻触：蛋体晃动、表面光泽、点击处星星 / 撒花粒子、轮换气泡。
- 长按：每满 1 秒可触发短震动，3 秒内最多 3 次；满 3 秒蛋壳发光并回应“我暖起来了”。
- 轻触和长按均不产生孵化进度、货币、奖励或每日完成记录。
- 反馈失败时不显示“未获得”，也不催促继续点击。

### 5.5 蛋壳创作

蛋壳颜色、星星 / 爱心 / 叶子、贴纸和手绘属于**免费创作工具**：

- 母版层：真实 `egg_base_day.webp`。
- 颜色层：低饱和半透明混色，透明度不高于 32%。
- 装饰层：图样、贴纸、圆形固定画笔和橡皮擦。
- 支持撤销、清空、保存和首页回显。
- 不开放用户图片上传。
- 不形成商品、背包、库存、稀有度或所有权。

### 5.6 命名

- 绑定成功后首次进入可弹出命名 bottom-sheet，并提供“暂不命名”。
- 未命名期间可以在每日首次进入时轻量提醒一次，不阻塞自由互动。
- 名字不超过 10 个中英文字或数字，空值和敏感词由服务端拦截。
- 改名每天最多 1 次，由服务端北京时间判定。
- 改名只更新昵称和收藏卡标题，不产生进度、奖励或关系变化。

## 6 · 破壳与收藏卡

### 6.1 破壳承接

物理装置按预设时间打开，用户先看到实体本体。小程序在服务端允许的承接时间内展示“查看破壳结果”，生成固定且可重试的同一结果。

- 首版不做蓝牙或联网硬件状态同步。
- 默认可在预设打开时间前 2 小时进入承接窗口，最终容差按装置时钟精度配置。
- 小程序不得在承接窗口前提前展示实体款式。
- 硬件提前打开、延迟打开或机械故障时，客服核验后可由后台人工承接同一固定结果。

### 6.2 收藏卡定位

用户侧统一称“收藏卡”。普通版中它是一蛋一份的纪念档案，不是卡牌收集系统。

收藏卡可以包含：

- 角色形象
- 原型
- 用户命名
- 实体款式
- 破壳日
- 星座
- 身份编号
- 一句第一人称自我介绍

不得包含：

- 稀有度、卡池、掉率、系列空卡位或集齐进度。
- 价格、收益、升值、交易或购买权解锁。
- 由互动成长决定的卡面完整度。

### 6.3 保存与分享

- 支持保存收藏卡图片。
- 支持微信好友分享和带小程序码的长图。
- 编号仅用于实体身份与售后。
- demo 收藏卡不得进入 live 卡册或正式统计。

### 6.4 收藏卡视觉与 H5 验收

- 视觉为柔和水彩水墨风，不使用 WAIC 宇宙海报风格。
- 卡面采用三段式：顶部名字 / 原型，中部服务端固定插画，底部生日 / 星座 / 身份信息与一句自我介绍。
- 视觉主次为插画 > 名字 > 数据；数据区不超过卡面约 1/3，每个字段只出现一次。
- 名字标题使用自托管的 Google Fonts OFL 版 `ZCOOL KuaiLe`，回退 `"PingFang SC", sans-serif`。
- H5 通过已备案 HTTPS 业务域名加载，由小程序注入固定 JSON；H5 不生成随机名字、插画、属性或业务时间。
- H5 canvas 经 `postMessage` 回传小程序，由 `wx.saveImageToPhotosAlbum` 保存；也可使用服务端固定图片 URL 作为备选。
- 分享长图包含完整卡面、实体身份编号和小程序码，并与屏显一致。
- 文本对比度达到 WCAG AA，弱动效下翻卡改为淡入。

## 7 · 破壳后陪伴

### 7.1 角色主页

- 角色主视觉。
- 一句定性状态。
- “和我说说话”主按钮。
- 场景入口。
- 收藏卡 / 档案入口。
- 长按角色保留贴贴反馈，不累积关系值。

### 7.2 生活场景

首版六场景：草地、雪地、房间、海边、书桌、天台。

- 互动点只返回动画和第一人称文案。
- 不产出卡片、货币、道具、成长值或商业权益。
- 所有互动点避开微信胶囊区和屏幕边缘。
- 离开页面时停止计时器和动画。
- 场景采用共用引擎 + 角色内容配置，不配置卡池。

### 7.3 定性状态

- 破壳后每天最多生成一句状态文案。
- 当天生成后保持稳定，次日可更新。
- 只表达平静、开心、好奇、想念等自然状态。
- 不生成心情值、好感度或关系等级。
- 久未访问时不责备、不惩罚、不制造愧疚。

### 7.4 对话

- 破壳后开放文字对话。
- 所有回复使用第一人称“我”，称用户为“你”。
- 不承诺人类身份，不鼓励情感依赖或排他关系。
- 用户输入和模型输出均经过内容安全检测。
- 危机、自伤、违法、未成年人敏感内容走专门兜底。
- 对话不解锁剧情、语音、动作或外观。

## 8 · 时间、节令与通知

- 业务时间以服务端北京时间 UTC+8 为准，不使用设备时间决定正式状态。
- 孵化房间的地理基准固定为上海，不申请用户定位权限。
- 天气由服务端拉取并缓存，前端只接收 `sunny / cloudy / rain / snow` 枚举；失败时回退 `sunny`。
- 昼夜只改变光线和措辞，不改变奖励或内容权益。
- 节气 / 节日只更新背景、问候和对话主题。
- 普通版不做限定掉落、节令发币、限定道具或连续回访奖励。
- 订阅消息只用于实体蛋服务节点，如即将破壳、可以查看破壳结果。
- 不发送“任务未完成”“奖励即将过期”等催促消息。

- 用户数据结构和删除要求见[技术与数据接口规格](./蛋宝宝小程序_技术与数据接口规格.md)。

## 11 · 成功指标

| 指标 | 观察目标 | 初始目标 |
|---|---|---|
| 激活码使用率 | 输入与核销是否顺畅 | ≥70% |

| 收藏卡保存率 | 是否具有纪念价值 | ≥50% |
| 收藏卡分享率 | 破壳时刻是否值得传播 | ≥25% |
| 对话开启率 | 是否愿意主动交流 | ≥60% |
| 7 日对话回访率 | 是否再次主动交流 | 首轮建基线 |
| 情绪价值满意度 | 是否认为“有回应、愿意再来” | 访谈 / 问卷建基线 |

所有数据查询强制 `mode='live'`；事件定义见技术规格。

## 12 · 当前实现与上线差距

### 12.1 已有能力

- 真实蛋体、四季昼夜背景、天气粒子、触摸反馈和窝垫实时阴影。
- 免费蛋壳换色、图样、贴纸、手绘、撤销、清空与保存。
- 固定孵化房间及小灯、咖啡机、画笔、围巾、窗户五个默认互动元素。
- 破壳、单张身份收藏卡、六个纯内容场景、文字对话和“我的”模块。
- 普通版生产路由、运行模式、请求适配和埋点均已按白名单收口。

### 12.2 上线前必须完成

1. CTO 后端完成用户身份、实体蛋、激活码核销、生命周期、服务端北京时间、天气、蛋壳创作、对话、收藏卡和注销删除接口。
2. 前后端联调所有失败、重试、幂等和异常恢复路径，任何成功状态均以后端确认结果为准。
3. 完成内容安全、隐私政策、未成年人保护、客服与注销删除流程的法务和平台审核。
4. 配置 H5 正式域名、可信 API 域名、静态资源 CDN 与小程序码。
5. 如保留内部 demo，必须使用独立构建、独立数据域和独立入口，且不能通过生产参数或远程配置开启。
6. 按[合规与提审清单](./蛋宝宝普通小程序_合规与提审清单.md)逐项签字确认。

### 12.3 内部展会 demo（非普通版提审包）

- 如保留 demo，只用于内部展示已批准的互动、对话和情绪价值内容。
- demo 必须提供明确退出方式，并使用独立构建、独立数据域和清晰的 demo 标识。
- 普通版提审包不注册 demo 入口，也不能通过用户参数、缓存、接口返回或远程配置进入。
- demo 不得写入正式用户、实体蛋、生命周期、收藏卡或统计数据。
- demo 产品行为和数据隔离需单独验收，不能作为普通版功能依据。

## 13 · 普通版验收标准

### 13.1 产品验收

- 新用户可以完成授权、输入激活码和绑定实体蛋。
- 首页只出现定性生命周期状态，不出现数值成长或货币。
- 轻触、长按、说话和蛋壳创作均有即时反馈。
- 所有互动均不产生进度、奖励、资源或权益。
- 破壳结果可重试但不会重复生成不同结果。
- 收藏卡没有稀有度、系列进度或商业解锁。
- 场景互动只产生内容反馈。
- 对话符合第一人称、内容安全和非依赖性要求。

### 13.2 构建验收

- 普通版 `app.json` 不注册商店、背包或游戏化页面。
- 生产包不包含可通过远程配置开启的游戏化入口。
- live 环境没有货币、库存、掉落、成长和任务数据表。
- demo 数据与 live 数据物理 / 逻辑隔离。
- 正式业务时间只来自服务端。
- `project.private.config.json` 不纳入版本控制。
