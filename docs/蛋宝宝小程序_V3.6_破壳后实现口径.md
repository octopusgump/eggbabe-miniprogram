## V3.6 破壳后落地

| 项目 | 当前口径 |
| --- | --- |
| 生活空间 | 固定左侧起居区、中间桌面、右侧布置区三屏连续空间；进入时定位到 ta 所在屏，用户可左右滑动查看空着的其他空间 |
| 此刻状态 | 以每只蛋的破壳时刻为起点，每 5 小时一个时段；同一时段刷新不改变 |
| 大场景 | 只使用家、旅行、打工、上学；用户不能手动选择；正式旅行目的地为大理、北京、西双版纳、东京 |
| 外出 | 三屏都显示空着的家，以第一人称文字说明去向，只提供写信；旅行期间不显示景区图，回家后可通过独立明信片查看预制旅途插画 |
| 对话 | 只在固定允许说话的居家小场景中原地出现输入；不注册独立聊天页 |
| 右下角操作 | 居家且允许说话时显示嘴巴对话按钮，外出时显示信件按钮；百宝箱收纳我的 / 设置、收藏卡、明信片和 ta 带回来的东西 |
| 对应动作 | 每个小场景只有一个审核过的固定动作；能否说话同样由固定映射决定 |
| 回忆 | 完成对应动作后才留下该时段的纪念物；外出写信后待 ta 回家再出现对应物；未访问或未行动的时段不补发 |
| 日常窗外 | 使用应用内稳定天气、真实本机日间 / 日落 / 夜晚与第一人称陪伴文案；不读取天气 API、定位或上海天气 |
| 魔法窗外 | 独立功能只允许大理、北京、西双版纳三张正式景区素材；它与旅行目的地不是同一资产池，东京成为正式旅行目的地不自动进入魔法窗；三张正式素材未齐前关闭入口 |
| 右侧布置区 | 本轮只保留空间边界。主 PRD 未放行 AI 生成额度、装饰列表与拖放存储，因此不注册相关页面和接口 |

## 状态与数据边界

- demo 数据存放在账号隔离的 `eggbabe_post_hatch_v36` 命名空间，用于状态、动作、寄信、回信与纪念物幂等回归。
- live 不由前端生成正式业务结果。环境视觉是例外：前端按稳定种子计算，不依赖天气 API；服务端只提供蛋身份字段和备案 CDN 根路径。
- live 端点为 `getPostHatchHome`、`performPostHatchAction`、`sendPostHatchLetter`、`getPostHatchMemories`。
- 服务端返回的小场景 ID 必须存在于固定场景表；前端以固定表覆盖动作、所在屏和说话权限，防止随机映射。
- `slot_end` 只用于到点重新请求，不展示倒计时或预告。

## 素材状态

所有运行时路径集中在 `miniprogram/config/post-hatch-assets.js`。破壳前中央裁图与破壳后三屏全景共享 36 个季节 × 天气 × 时段 key；每个 key 必须同时具备 `941×1672` 的预孵化 WebP 和 `2823×1672` 的破壳后全景 WebP。资源缺失直接显示加载失败与重试，禁止以其他天气场景兜底。项目目录保留源资产；正式运行由 bootstrap 的 `environment_cdn_base` 拼出备案 CDN 地址。

当前左右屏正式状态素材、完整角色姿态、明信片、心情头像以及三张正式魔法窗景区图仍未齐；页面保留清晰配置边界，不把参考合成图、草稿或第三方图片接入正式配置。东京已确认为正式旅行目的地，但现有东京图片仍是候选，须按《蛋宝宝旅行明信片内容与美术规格 v1.0》逐张终审并晋级后才能接入。已有透明单件纪念物会按明确 ID 复用。
