## 1 · 产品申报定位

当前产品只申报：

- 实体蛋激活、绑定和生命周期服务。
- 蛋体自由触摸与即时视觉 / 触觉反馈。
- 免费蛋壳颜色、贴纸与手绘创作。
- 非数值化状态和第一人称对话。
- 生活场景中的纯内容互动。
- 一蛋一份的收藏卡纪念档案。

不得用“陪伴工具”文案包装后台仍在运行的成长、任务、奖励、货币、掉落或解锁机制。审核判断看实际功能。

## 2 · 风险标记

| 标记 | 含义 | 发布处理 |
|---|---|---|
| 🟩 普通版保留 | 陪伴服务和纯内容互动 | 可以进入生产 |
| 🟨 普通版改写 | 概念可留但须移除游戏机制 | 修改后复核 |
| 🟥 普通版停用 | 高度游戏化或当前资质不足 | 不注册、不展示、不调用、不采集 |
| 🟦 未来游戏版 | 仅供独立游戏立项 | 不进入普通版排期 |
| ⚖️ 待平台 / 法务确认 | 尚无可留档结论 | 确认前不发布 |

## 3 · 普通版功能白名单

### 3.1 可以上线

- 激活码输入、核销与实体蛋绑定。
- 服务端生命周期阶段。
- 真实蛋体、呼吸、触摸回弹、光泽、阴影和弱动效。
- 免费蛋壳换色、图样、贴纸和手绘。
- 无任务、无奖励的自由陪伴入口。
- 一蛋一份收藏卡。
- 定性状态、纯内容场景和安全对话。
- 账户、隐私、注销、帮助与邮件支持（`hello@eggbabe.com`）。
- 必要的服务质量和可用性埋点。

### 3.2 必须停用

| 规则 ID | 必须停用 |
|---|---|
| C-01 | 孵化百分比、成长值、好感度、关系等级 |
| C-02 | 每日任务、首次完成奖励、签到、连续到访 |
| C-03 | 露珠、金币、钻石或任何虚拟资源余额，以及点击阈值、日上限和运营补发 |
| C-04 | 商店、背包、购买、库存、装配、摆放、投喂道具 |
| C-05 | 随机掉落、卡池、抽取、稀有度、限定资源 |
| C-06 | 卡片系列、空卡位、集齐、成就或权益解锁 |
| C-07 | 排行榜、PK、竞技、抽奖、转盘、盲盒 |
| C-08 | 虚拟资源充值、真钱虚拟物品、付费加速 |
| C-09 | 激励广告换资源 |
| C-10 | 游戏化邀请奖励、分享拉新奖励 |

**禁止仅替换“掉落 / 抽卡”为“遇见 / 收集”后继续运行同一机制。**

主 PRD 或技术文档引用红线时应引用规则 ID，不另建一套等价规则。主 PRD 升版时，本清单必须重新复核并更新“适用版本”，不得自动向后继承。

## 4 · 数据与构建门禁

- [ ] 普通版 `app.json` 未注册商店、背包或游戏化页面。
- [ ] 首页、我的、分享卡和订阅消息没有游戏化入口。
- [ ] 生产包不能通过远程配置重新开启 🟥 功能。
- [ ] live 后端没有货币、流水、库存、掉落、成长、任务或关系值 schema。
- [ ] live 不发送历史游戏事件。
- [ ] demo 使用独立构建、独立命名空间和独立统计域。
- [ ] demo 数据不进入正式余额、卡册、用户画像或指标。
- [ ] H5 不生成随机名字、插画、业务时间或正式业务结果。
- [ ] 正式业务时间只使用服务端北京时间 UTC+8。

## 5 · 用户界面与文案检查

- [ ] 品牌英文只写 `eggbabe`。
- [ ] 用户侧卡片统一称“收藏卡”。
- [ ] 不出现“任务、奖励、获得、掉落、稀有、集齐、解锁、升级、养成”等游戏化引导。
- [ ] 不显示隐藏成长值、剩余点击、达成进度或每日完成情况。
- [ ] 不出现“再点一次”“今天还没完成”等催促。
- [ ] 不因久未访问表现饥饿、低落、责备或失望。
- [ ] 不暗示收藏卡价格、收益、升值或交易价值。
- [ ] 第一人称文案与实际后台逻辑一致。

## 6 · 内容、隐私与未成年人

- [ ] 用户输入和模型输出均接入内容安全检测。
- [ ] 对话包含自伤、违法、未成年人敏感内容的危机兜底。
- [ ] 对话不鼓励情感依赖、排他关系或替代现实人际关系。
- [ ] 隐私政策披露实际收集字段、用途、保存期限和删除方式。
- [ ] 不采集普通版不需要的兴趣画像、成长、集卡或经济数据。
- [ ] 账号注销支持冷静期取消和到期后的依法处理。
- [ ] 头像、对话、蛋壳创作等数据采用必要的权限和访问控制。

## 9 · 普通版到游戏版的迁移门禁

**普通小程序走到游戏小程序不是“在原账号里打开功能开关”。**

| 阶段 | 产品状态 | 门禁 |
|---|---|---|
| P0 合规收敛 | 关闭全部 🟥 功能 | 生产白名单、构建隔离、文案扫描 |
| P1 普通陪伴版 | 互动 + 对话 + 情绪价值 | 服务类目预审、隐私和安全就绪 |
| P2 价值验证 | 不增加游戏系统 | 完成 8–12 周真实验证 |
| G0 独立游戏立项 | 建立游戏产品线 | 主体、名称、著作权、出版单位、运营资质、平台账号 / 类目、防沉迷方案核验 |
| G1 出版与平台审批 | 申报版本 | 按主管部门、出版单位和平台要求取得全部批准 |
| G2 游戏版上线 | 只发布获批内容 | 版本、名称、主体、支付和防沉迷持续合规 |

在微信给出可留档结论前，游戏版按独立账号 / 类目、独立发布包、独立后端域和数据边界规划。普通版用户数据能否迁移另行评估。
